### 0.3 이 설계가 보장하지 않는 것

- 안건의 "결정"을 선취하지 않는다 — 스파이크 실행 시기·부품 구성은 8월 초 체크포인트, 동역학 편입·실지원 시점은 2026.11 분기 재평가에서만 판단한다.
- 시장 조사 사실(채용 규모, JD 요구, 제도 변경)의 재검증을 하지 않는다 — 2026-07-20 웹 검색 기준이며, 사후지급금 폐지는 법령 원문 미확인 상태다.
- 이 동기화가 v1/v1.5 산출물 진척 자체를 만들지 않는다.

## 1. 현재 구조 진단 (레포 사실 기반)

2026-07-20 로컬 검증에서 확인된 사실:

- **진행 상태**: notes.md 기준 순서 1-4 완료(6/29, 계획 페이스 충족, 절삭 규칙 미발동), 순서 5 체크박스 전부 완료 표기, 순서 6 착수(week1 정독 완료). 단 진행 표 상태 열은 순서 5 "대기", 순서 6 "대기"로 미갱신 — 보드 내부 불일치.
- **8월 초 체크포인트**: 이미 조기 수행됨(2026-06-29 노트 + 2026-07-07 갱신). 결론: Phase 4.5 전면 조기 진입 보류, Section 0 만 2026.08 로 전진, Sections 1-3 은 2026.09-11. `Roadmap/Phase 4.md` 진행 원칙의 "1순위 검토 안건: 9-10월 조기 진입" 문구는 기결 사안을 미결로 남긴 잔재.
- **dry-run 기록 간극**: 순서 5 의 "결과 표 정리 — 여기까지가 v1 레포 기록" 체크에도 불구하고, 전체 루프 dry-run 수치의 기록 위치가 레포에서 확인되지 않음. README Evidence 는 `predict_action` 단독 수치뿐이고 `Measurements/openvla-rtx4070-int4/methodology.md` 는 전체 루프를 "별도 측정" 미래형으로 기술.

### 2.3 타이밍 리스크와 원칙 충돌

- 현재의 대규모 채용은 파도이며 2027.03 복직 시점 문턱 상승 가능성 실재. 완화 요인: 제품 출시 전 조직 확장 진행형, 채용 파도 반복 가능성. 리스크 유형은 "자리 소멸"보다 "문턱 상승" — 문턱은 포트폴리오로 넘는다는 기존 전략과 일치.
- 조기 지원 논거: 육아휴직 급여 사후지급금 폐지(2025.01, 전액 즉시 지급 — 웹 확인, 법령 원문 재확인 필요)로 경제 페널티 소멸. 채용 프로세스 1-3개월 감안 시 2027.01 지원 = 복직(2027.03)과 접속 가능. 잔존 변수: 휴직 중 지원 사실의 고용주 마찰, probe 가시성 원칙의 설계 의도, 좁은 업계의 평판 관리.
- 처리: 즉흥 변경 금지. 2026.11 분기 재평가 정식 안건으로만 판단한다.

### 3.8 레포 비공개 유지 + 산출물 repo 분리 반영

- README "Repo 운영 방식"에 정책 명시: 이 레포는 비공개 유지(2026-07-20 결정), 문서 내 "공개"/"리포 내 공개"는 "이 레포에 기록"을 뜻하며, 외부 공개 증거·산출물(실측 Evidence 요약, v1.5 블로그 동반 코드, v2·v3)은 **별도 공개 산출물 repo** 에서 발행한다.
- probe 1단의 "학습 리포 공개 증거 정비"를 "공개 증거 정비 — 별도 산출물 repo 신설"로 교체 (타임라인 표·probe 절·커리어 경로 3곳).
- 부록 B 인트로에 외부 공개 발행처(산출물 repo) 명시.
- notes.md git filter-repo 항목 방향 갱신: 이 레포 비공개 유지로 이 레포의 author 재작성은 사실상 불요 예상 — 산출물 repo 를 처음부터 올바른 신원으로 생성하는 것으로 대체하고, 8월 초 체크포인트에서 최종 확정.
- 산출물 repo 의 구조·이관 범위(Evidence 요약, 재현 스크립트 등)는 신설 시(늦어도 v1.5 공개 전) 별도 결정 — 본 spec 범위 밖.
- 익명 표기는 비공개 유지 결정 후에도 계속 유지한다 — 산출물 repo·블로그로 문서 일부가 이관·인용될 수 있다.

## 8. 의사결정 로그

### 8.1 스파이크 전진 안건의 귀속: 2026.11 재평가 vs 8월 초 체크포인트
- **옵션 A (비채택)**: 2026.11 분기 재평가 안건 상정 — 검토 원본의 원안. 실행 후보 시기(2026.08-09)가 심의 전에 지나가므로 시점상 모순.
- **옵션 B (채택)**: 8월 초 정식 체크포인트(기존 결정 기구, 입력: 7월 실적) 안건으로 귀속.
- **사유**: 기존 메커니즘 재사용 + 시점 정합. 8월 실행안은 GPU 종속 작업 과밀(§1)로 배제되고 9월 절충안만 심의 대상.

### 8.2 회사 표기: 실명 vs 익명
- **옵션 A (비채택)**: 실명 기재 — 검토 편의는 있으나 공개 원격에 타겟사·이직 의도가 노출.
- **옵션 B (채택)**: 기존 익명 관행 유지 ("Dynamixel 제조사" 등).
- **사유**: 레포 본문의 기존 관행과 일관, 고용주 노출 리스크 차단.

### 8.3 검토 원본: 보존 vs 삭제
- **옵션 A (비채택)**: 레포에 커밋 보존 — 실명·사적 논의(불안 진단 등) 노출.
- **옵션 B (채택)**: 반영분을 본 spec §2 로 승계 후 삭제 (untracked 상태라 이력 잔존 없음).
- **사유**: 커밋 불가 정보와 반영 필요 정보의 분리.

### 8.4 동역학 트랙: 즉시 편입 vs 안건화
- **옵션 A (비채택)**: 즉시 편입 — 총 예산(주 6-8시간)이 휴직 기간에 이미 만재라 대체 대상 결정 없이는 과적재.
- **옵션 B (채택)**: 2026.11 안건화 + 문안에 시간 예산 트레이드오프 조건 명시.
- **사유**: 시간 예산 우선 원칙(README 핵심 원칙 7)과 정합.

### 8.5 공개 전략: 단일 repo 공개 vs 학습/산출물 repo 분리
- **옵션 A (비채택)**: 이 레포를 공개 전환해 산출물·증거를 직접 어필 — 계획·커리어 문서(휴직 일정, 재평가 안건, 이직 전략)가 함께 노출되고, 학습 로그와 산출물이 섞여 면접관 진입점이 흐려진다.
- **옵션 B (채택)**: 이 레포 비공개 유지 + 공개 산출물 전용 repo 분리 (2026-07-20 사용자 결정).
- **사유**: 커리어 민감 정보 차단 + 산출물 큐레이션 품질. 커밋 그래프·공개 증거 지표는 산출물 repo 가 담당한다.
