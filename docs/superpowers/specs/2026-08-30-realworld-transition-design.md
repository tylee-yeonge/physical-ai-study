## 0. TL;DR

- **v1.5 는 OpenVLA 로 그대로 마감한다.** 성공 기준 (설계-실행-정량 분석) 은 이미 성립했고, 모델 세대는 둘째 층 증거의 유효성을 깎지 않는다. 갈아엎기는 주 6-8시간 예산에서 최악의 거래다.
- **sim 에서 2번째 모델을 돌리는 중간 단계 (v1.6) 는 만들지 않는다.** SmolVLA 는 LeRobot 커뮤니티 SO-100/101 데이터로 사전학습돼 실기 zero-shot 이 0% 에 붙지 않을 가능성이 높다 — sim 경유 없이 실기에서 before/after 가 성립한다.
- **SO-101 을 즉시 확보하고 실기로 직행한다**: 스파이크 2026.09 첫 2주 (LeRobot 네이티브) → 판정 2026-09-21 1회 → Stage 1 본 빌드 2026.10-11 → **v2.5 (SmolVLA 실기 before/after) 2026.11-12.** 리포가 Phase 7 (2027.08) 로 미뤄둔 "둘째 층 증거의 real 승격"이 약 1년 당겨져, 2027.03 실지원에 real 증거를 들고 간다.
- **역할 분리로 스택 이중화를 증거로 바꾼다**: 데이터·학습 = LeRobot, 배포·통합 = ROS2. LeRobot 직결 vs ROS2 경유의 latency 차 = "통합 오버헤드" — 셋째 층 수치.
- **되돌림 조건 명문화**: teleop 불가 또는 스파이크 2주 초과 → 원안 일정 (10월 스파이크·12월 Stage 1·2027.03 v2.5) 복귀. 판정은 2026-09-21 한 번만 — 즉흥 변경 금지.

## 2. 결정 1 — v1.5 는 OpenVLA 로 마감한다

### 2.1 판정

**마지막 week (Section 3: eval N회 + before/after 분석 + 블로그) 를 그대로 완주한다.** 재작업 없음.

### 2.2 근거

1. Phase 4.5 성공 기준은 결과 비의존 — "adaptation 파이프라인을 설계-실행하고 결과를 정량 분석했다". OpenVLA 로 이미 성립했다.
2. 갈아엎으면 잃는 것은 6-8주 산출물, 얻는 것은 같은 산출물의 신모델판 하나. 교체의 가치는 v2.5 (real) 가 더 크게, 더 싸게 회수한다.
3. 하네스 검증 (상한 20/20·하한 1/20)·eval N회/분산 코드·부분 도달률 지표는 모델 무관 자산이라 v2.5 로 이식된다 — v1.5 를 완주해야 이식할 원본이 완성된다.

### 2.3 블로그 처리

선정 시점 (2026.06) 과 마감 시점 사이의 필드 변화를 한 단락으로 명시하고, "다음 단계는 같은 eval 논리에 새 모델을 — 실기에서 — 넣는 것"으로 맺는다 (근거 원본 §3.2 초안). 결점 고백이 아니라 필드를 읽고 있다는 신호 + v2.5 블로그 (real 후속편) 예고.

## 3. 결정 2 — sim v1.6 은 만들지 않는다

### 3.1 검토 초안과 폐기 경위

트렌드 검토 초안은 "v1.6: 동일 하네스 2번째 모델 (sim, SmolVLA)" 신설을 제안했다 — v1.5 하네스를 재사용해 2-3주에 AR vs chunk 비교표를 만드는 안. 같은 날 실기 전환 plan 이 확정되며 폐기했다.

### 3.2 폐기 논리

sim v1.6 의 존재 이유는 "새 모델 실측을 싸게 확보"였다. 그런데:

- SmolVLA 의 사전학습 분포 (SO-100/101 실기) 를 고려하면 **실기가 sim 보다 zero-shot 신호가 살아있을 가능성이 높다.** sim (ManiSkill) 은 오히려 SmolVLA 에게 미학습 분포다 — v1.5 가 OpenVLA 에서 겪은 "환경 정합 vs 미학습 분포" 문제를 반대 방향으로 다시 겪는 자리다.
- 실기 전환 후 sim v1.6 산출물은 v2.5 에 완전히 포함된다 (같은 모델, 같은 eval 논리, 더 강한 도메인). 부분집합을 먼저 만들 이유가 없다.
- 주 6-8시간 예산에서 9-11월 메인 트랙은 하나여야 하고, 그 자리는 하드웨어가 가져간다.

### 3.3 초안에서 살아남는 것 (v2.5 로 이관)

1. **동일 조건 비교 원칙** → v2.5 비교표: OpenVLA int4 (sim, v1.5) vs SmolVLA (real, v2.5), latency 축은 스파이크 must 기준 4 에서 선확보.
2. **모델 무관 하네스 설계** → LeRobot policy 인터페이스 기준 — 2번째 모델 (GR00T N1.7) 투입 비용을 1-2주로 고정.
3. **eval 자산 이식** — N회/분산 코드, 부분 도달률, "도메인 갭 vs 통합 버그" 구분 논리.

## 4. 결정 3 — 실기 전환 (SO-101 조기 확보)

### 4.1 확정 경로

절차·통과 기준·주차표·구매 체크리스트의 원본은 [실기 전환 plan](../plans/2026-08-30-realworld-transition-plan.md) 이다. 구조만 요약한다.

| 단계 | 시점 | 게이트 |
|---|---|---|
| SO-101 구매 | 즉시 (2026.08 말-09 초) | — (리드타임 3일) |
| 스파이크 (LeRobot 네이티브) | 2026.09 첫 2주, 타임박스 | must 4: teleop / 10 에피소드 녹화+Hub / SmolVLA zero-shot 실행 / latency 측정 |
| **판정** | **2026-09-21, 1회만** | 통과 → 아래로. teleop 불가 또는 2주 초과 → **롤백** (§6) |
| Stage 1 본 빌드 | 2026.10-11 | 완성도 + ROS2 층 + 안전 기초 + URDF + 1분 영상 |
| v2.5 | 2026.11-12 | SmolVLA 실기 before/after (N≥20, 분산·부분 도달률) — 성공 기준은 v1.5 와 동일 (결과 비의존) |

### 4.2 왜 스파이크를 ROS2 가 아니라 LeRobot 네이티브로 재정의하는가

원안 스파이크 (2026.10) 는 `feetech_ros2_driver` + ros2_control 검증이었다. 실기 전환에서 가장 먼저 죽여야 할 리스크는 "팔이 LeRobot 파이프라인으로 도는가" (teleop → 녹화 → 정책 실행) 다 — v2.5 의 성립 조건이 그것이고, ROS2 래핑은 v2.5 가 아니라 v3 (배포·통합) 의 성립 조건이다. 리스크 순서에 맞춰 ROS2 는 Stage 1 must 로 이동한다.

- **역할 분리**: 데이터·학습 = LeRobot / 배포·통합 = ROS2. 이중화는 리스크가 아니라 측정 대상 — Stage 1 에서 (a) LeRobot 직결 vs (b) ROS2 토픽 경유 latency 를 재고, (b)-(a) 를 "통합 오버헤드"라는 셋째 층 수치로 쓴다.
- **원칙 정합**: README 핵심 원칙 8 "가장 중요한 증거 = 가장 먼저 리스크 검증". 가장 중요한 증거는 이제 real before/after 이고, 그 리스크 검증 (스파이크) 을 가장 앞으로 당기는 것이 본 결정이다.

### 4.3 영향 범위

- **당겨지는 것**: 스파이크 (10월→9월), Stage 1 (12월→10월), v2.5 (2027.03→2026.11), real 둘째 층 증거 (Phase 7 2027.08 → v2.5 2026.12).
- **바뀌지 않는 것**: Phase 5·6 일정, v2 (Isaac Sim 디지털 트윈)·v3 정의, 휴직 중 구직 지원 금지, "메인 1트랙" 원칙 (9-11월 메인 = 하드웨어), 분기 재평가 메타룰.
- **재평가 #1 (2026.11) 입력 변경**: "OpenVLA 후속 모델 등장 여부" (결과 확정으로 소멸) → "스파이크 판정 결과 / v2.5 진행률 / 2번째 모델 (GR00T N1.7) 투입 여부".

## 5. 결정 4 — 모델 선택: SmolVLA 주 대상, GR00T N1.7 옵션

| 판단 축 | SmolVLA (주 대상) | GR00T N1.7 (옵션) |
|---|---|---|
| 크기 / 라이선스 | 450M / Apache 2.0 | 3B / Apache 2.0 |
| 파인튜닝 | **로컬 4070 12GB 가능** | 24GB 급 — RunPod 여유 시 |
| 액션 헤드 | flow-matching action chunk | DiT action chunk |
| SO-101 정합 | 사전학습 데이터가 SO-100/101 커뮤니티 데이터셋 | egocentric 사전학습, cross-embodiment |

선택 이유: (a) v2.5→v3 가 LeRobot 포맷으로 통일돼 "확립한 파이프라인의 real 확장" 서사가 코드 수준에서 성립, (b) 로컬 학습으로 RunPod 리스크 소멸 — v1.5 실측이 이미 "비용의 23% 가 체크포인트 저장"을 보여줬다, (c) 450M 의 빠른 실험 회전. GR00T N1.7 투입 여부는 재평가 #1 안건 — 투입 시 "복수 모델 × 단일 embodiment" 증거가 부산물로 생기지만, cross-embodiment 를 표제로 승격하지 않는 원칙은 유지한다.
