## 📚 핵심 개념: 왜 스케일을 모르는가

### 1. 핀홀 모델의 근본적 한계

**투영의 본질:**
```
3D 점 X = [X, Y, Z]^T 가 있을 때

투영: x = K * (R*X + t) / Z_c

여기서 핵심:
  λ * x = K * [R|t] * X

→ 3D 점 X 와 λX (스케일이 다른 점)가
  동일한 2D 픽셀에 투영된다!
```

**시각화 (같은 이미지를 만드는 두 장면):**
```
장면 A (실제 크기):          장면 B (2배 크기):

      ● (1m 앞 작은 공)           ● (2m 앞 큰 공)
     /                           /
    /                           /
카메라 ──────→               카메라 ──────→

촬영 결과:                   촬영 결과:
┌──────────┐                ┌──────────┐
│    ●     │                │    ●     │
│          │                │          │
└──────────┘                └──────────┘
     ↑                           ↑
     └───── 동일한 이미지! ──────┘
```

**수학적 증명:**
```
투영 방정식:
  λ₁ * [u]     [X]
       [v] = K [R|t] [Y]
       [1]     [Z]
               [1]

만약 3D 점을 s배 스케일, 이동을 s배 스케일하면:
  λ₂ * [u]     [sX]
       [v] = K [R|st] [sY]
       [1]      [sZ]
                [1]

→ λ₂ = s * λ₁ 이지만
→ 투영된 픽셀 (u, v)는 동일!

결론: 단안 카메라는 스케일 s를 결정할 수 없다
```

---

### 2. Essential Matrix와 스케일

**Essential Matrix 복원 과정:**
```
Step 1: 특징점 매칭
  (u₁, v₁) ↔ (u₂, v₂)

Step 2: Essential Matrix 계산
  x₂^T E x₁ = 0
  E = [t]× R

Step 3: E에서 R, t 분해
  SVD(E) → R, t 복원

⚠️ 문제: t는 "방향"만 알 수 있다!
```

**왜 t의 크기를 모를까?**
```
에피폴라 제약: x₂^T [t]× R x₁ = 0

만약 t를 αt로 바꾸면:
  x₂^T [αt]× R x₁ = α * (x₂^T [t]× R x₁) = 0

→ 어떤 α를 곱해도 제약이 만족됨!
→ t의 크기(norm)는 결정 불가

관례: ||t|| = 1 로 정규화
```

**정규화의 의미:**
```
실제 이동: t_real = [0.3, 0, 0.5]  (미터 단위)
                     ||t_real|| = 0.583m

정규화 후: t_norm = [0.514, 0, 0.857]
                     ||t_norm|| = 1.0  (단위 없음!)

→ 방향 (0.514 : 0 : 0.857) 은 정확
→ 크기 0.583m 는 사라짐

이후 삼각측량한 3D 점도
실제와 다른 스케일을 가짐!
```

---

### 3. 초기화 시 스케일 결정

**VO 초기화:**
```
Frame 0 → Frame 1:
  E 분해 → R₀₁, t₀₁  (||t₀₁|| = 1)

삼각측량 → 3D 점 생성

이 시점에서:
  - 전체 맵의 스케일이 "임의"로 결정됨
  - ||t|| = 1이 "1미터"를 의미하지 않음!
  - 1일 수도 있고, 0.01일 수도 있고, 100일 수도 있음

┌─────────────────────────────────────┐
│  실제 세계: 카메라가 30cm 이동       │
│  SLAM 세계: 카메라가 1.0 이동        │
│  → 스케일 = 0.3 (알 수 없음!)       │
└─────────────────────────────────────┘
```

## 📉 스케일 드리프트

### 1. 스케일 드리프트란?

**정의:**
```
스케일 드리프트 (Scale Drift) =
  매 프레임마다 추정하는 스케일이 조금씩 달라져서
  오차가 누적되는 현상

원인:
  - 프레임마다 독립적으로 t 추정
  - 각 t의 스케일이 미세하게 다름
  - 이전 프레임의 스케일 오차가 다음 프레임에 전파
```

### 2. 오차 누적 과정

**예시: 직선 이동 (실제 1m씩 10번):**
```
프레임 쌍  | 실제 이동 | 추정 스케일 | 추정 이동 | 누적 위치
---------- |----------|-----------|----------|----------
0 → 1     |   1.0m   |   1.00    |   1.0m   |   1.0m
1 → 2     |   1.0m   |   0.95    |   0.95m  |   1.95m
2 → 3     |   1.0m   |   1.03    |   1.03m  |   2.98m
3 → 4     |   1.0m   |   0.97    |   0.97m  |   3.95m
4 → 5     |   1.0m   |   1.02    |   1.02m  |   4.97m
...        |   ...    |   ...     |   ...    |   ...
9 → 10    |   1.0m   |   0.98    |   0.98m  |   9.72m

실제 위치: 10.0m
추정 위치:  9.72m
오차: 0.28m (2.8%)

→ 100프레임이면?  오차 ~2.8m!
→ 1000프레임이면? 오차 ~28m!!
```

### 3. 시각화: 원형 궤적에서의 드리프트

```
실제 궤적 (원):              스케일 드리프트 있는 추정:

        ●●●●●                        ●●●●●
      ●       ●                    ●       ●
    ●           ●                ●           ●
   ●      시작   ●              ●             ●
    ●    /끝    ●                ●              ●
      ●       ●                   ●              ●
        ●●●●●                       ●●●●●●        ●
                                              ●●●●●●
     원점 복귀!                      시작과 끝이
                                   맞지 않음!

원인:
  - 매 프레임 1%씩 스케일 오차
  - 반 바퀴: 반지름이 조금 커짐
  - 전체: 나선형으로 벌어짐
```

### 4. 스케일 드리프트의 영향

```
영향 1: 맵 왜곡
  ┌────────────────────────────────┐
  │ 실제 방:  5m x 5m             │
  │ SLAM 맵: 5m x 4.3m (찌그러짐) │
  └────────────────────────────────┘

영향 2: 경로 계획 실패
  ┌────────────────────────────────┐
  │ 실제 거리: 장애물까지 2m       │
  │ SLAM 추정: 장애물까지 1.7m     │
  │ → 충돌 위험!                   │
  └────────────────────────────────┘

영향 3: Loop Closure 실패
  ┌────────────────────────────────┐
  │ 같은 장소를 재방문해도          │
  │ 스케일이 달라서 인식 실패       │
  │ → 드리프트 교정 불가           │
  └────────────────────────────────┘
```

## 🔄 Sim(3) 정렬 (간단 소개)

### SE(3) vs Sim(3)

```
SE(3): 강체 변환 (회전 + 이동)
  T = [R  t]    ← 6 자유도
      [0  1]

Sim(3): 유사 변환 (회전 + 이동 + 스케일)
  S = [sR  t]   ← 7 자유도
      [0   1]

새로운 파라미터: s (스케일)

왜 필요한가?
  - 두 단안 맵을 정렬할 때
  - Loop Closure에서 스케일 차이 보정
  - Ground truth와 비교할 때
```

### 활용 예시

```
ORB-SLAM의 Loop Closure:

1. Loop 감지 (같은 장소 재방문)
2. 현재 맵과 이전 맵의 스케일이 다름!
3. Sim(3) 최적화로 스케일 + 포즈 동시 정렬

   현재 맵 (스케일 s₁)  ──Sim(3)──→  이전 맵 (스케일 s₂)

4. 전체 맵에 스케일 보정 전파
```

### 예시: ATE (Absolute Trajectory Error) 계산

```
Ground truth 궤적과 SLAM 궤적 비교:

1. SLAM 궤적은 스케일이 다름
2. Sim(3) 정렬로 스케일 맞춤:
   s*, R*, t* = argmin Σ ||p_gt - (s*R*p_slam + t*)||²
3. 정렬 후 ATE 계산

이것이 논문에서 "Sim(3) aligned ATE"라고 부르는 것!
```

## 🔍 자체 점검

### 질문 1: 근본 원인
**Q:** 단안 카메라가 스케일을 결정할 수 없는 근본적인 이유는?

**A:**
```
투영의 본질:
  3D 점 X와 λX가 같은 2D 픽셀에 투영됨

  λ * [u, v, 1]^T = K * [R|t] * [X, 1]^T

→ 깊이(Z)와 스케일(λ)이 결합되어
  하나의 이미지만으로는 분리 불가

이는 수학적으로 피할 수 없는 한계!
깊이 센서(LiDAR, RGB-D) 또는
관성 센서(IMU)가 필요한 이유
```

### 질문 2: 정규화
**Q:** Essential Matrix에서 t를 ||t||=1로 정규화하는 이유는?

**A:**
```
에피폴라 제약: x₂^T [t]× R x₁ = 0

이 식에서 t를 αt로 바꿔도 성립:
  x₂^T [αt]× R x₁ = α * 0 = 0

→ t의 크기는 자유 파라미터
→ 유일한 해를 위해 ||t|| = 1로 고정

이는 "방향만 알 수 있다"는 것을 의미
실제 이동 거리는 알 수 없음
```

### 질문 3: 스케일 드리프트
**Q:** 스케일 드리프트가 왜 위험한가?

**A:**
```
1. 오차가 누적됨 (발산)
   - 매 프레임 1% 오차면
   - 100프레임: ~37% 오차 (1.01^100 = 2.7)
   - 크기가 2.7배 달라질 수 있음!

2. 보정이 어려움
   - 과거 프레임 다시 처리 필요
   - 실시간 시스템에서 부담

3. 다른 센서와 융합 어려움
   - GPS와 좌표 맞추기 불가
   - 다른 로봇과 맵 공유 불가
```

### 질문 4: Stereo vs Mono
**Q:** 스테레오 카메라는 왜 스케일을 알 수 있는가?

**A:**
```
스테레오 카메라:
  좌 카메라 ←── b (baseline) ──→ 우 카메라

baseline b = 물리적으로 측정된 값 (예: 12cm)

깊이 계산:
  Z = f * b / d  (d = disparity)

여기서 f, b는 "미터 단위"로 알려져 있으므로
Z도 "미터 단위"로 결정됨!

→ 절대 스케일 복원 가능
→ 스케일 드리프트 없음 (이론적으로)
```

## 🎯 핵심 요약

1. **스케일 모호성의 원인**
   - 핀홀 투영: X와 λX가 같은 픽셀에 투영
   - Essential Matrix: t의 방향만 결정 가능
   - ||t|| = 1 정규화 → 실제 크기 정보 소실

2. **스케일 드리프트**
   - 매 프레임 스케일 오차가 누적
   - 긴 궤적에서 맵이 실제와 크게 달라짐
   - 단안 VO/SLAM의 가장 큰 약점

3. **Sim(3) 정렬**
   - SE(3)에 스케일 자유도 추가 (7 DoF)
   - Loop Closure, 평가에서 스케일 보정
   - ORB-SLAM 등에서 실제 사용

4. **해결 방법 (Week 13에서 상세히)**
   - 스테레오/RGB-D: 직접 깊이 측정
   - IMU 융합 (VIO): 가속도로 스케일 관측
   - 알려진 물체 크기 활용
   - Ground plane 제약

5. **실무적 의미**
   - 단안 SLAM 결과는 항상 "상대적"
   - 실제 단위(미터)로 변환하려면 추가 정보 필요
   - 논문에서 ATE 보고 시 Sim(3) 정렬 필수
