## 📚 핵심 개념 자세히 알아보기

### 1. 2D-2D 모션 추정이 뭐죠?

**쉬운 비유:**
```
상황: 눈을 감고 한 발짝 걸음
질문: "몇 cm 걸었고, 어느 방향으로 돌았어?"
방법: 앞뒤 사진 2장 비교하기!
```

**정식 설명:**
두 장의 이미지에서 **같은 점들(대응점)**을 찾아서, 카메라가 **얼마나 회전(R)하고 이동(t)했는지** 계산하는 방법입니다.

**언제 사용하나요?**
- ✅ **VO 초기화** - 맨 처음 시작할 때 (3D 정보가 아직 없음)
- ✅ **Relocalization** - "어? 여기 어디지?" (잠깐 길을 잃었을 때)
- ✅ **3D 맵이 없을 때** - 처음부터 시작해야 할 때

### 2. Essential Matrix (E) - 핵심 도구 이해하기

#### 먼저, 에피폴라 기하학(Epipolar Geometry)이 뭔가요?

**비유로 이해하기:**
```
상황: 친구 둘이서 같은 물체를 다른 각도에서 봄

👁️ 카메라 1 (왼쪽)    📦 물체    👁️ 카메라 2 (오른쪽)

질문: 카메라 1에서 본 점이 카메라 2에서는 어디쯤에 보일까?
답: 일직선(에피폴라 선) 위 어딘가에 있을 거예요!
```

**에피폴라 제약(Epipolar Constraint):**
```
수식: p2^T * E * p1 = 0

설명:
  p1: 첫 번째 이미지의 점
  p2: 두 번째 이미지의 같은 점
  E: Essential Matrix (두 카메라 관계를 담은 3x3 행렬)
```

**왜 중요한가요?**
```
일반적인 경우: "저 점이 다음 이미지 어디에 있을까?"
                → 전체 이미지(640×480 = 307,200 픽셀)에서 찾아야 함 😱

에피폴라 제약: "에피폴라 선 위에만 있을 거야"
               → 한 줄(640픽셀)만 찾으면 됨! 😊
               → 480배 빠름!
```

#### Essential Matrix는 뭘 담고 있나요?

```
E = t^ * R

설명:
  R (Rotation): 카메라가 얼마나 회전했는지
  t (Translation): 카메라가 어느 방향으로 이동했는지
  t^: t의 외적 행렬 (수학적 트릭)
```

**E의 성질:**
- 3×3 행렬
- Rank 2 (한 줄이 다른 줄들의 조합)
- 자유도 5 (회전 3 + 이동 방향 2)

### 3. Essential Matrix 추정하기 - 단계별 설명

#### Step 1: 대응점 찾기

**목표:** 두 이미지에서 "같은 점" 찾기

```
이미지 1:                 이미지2:
  📍 책상 모서리 (100, 150) ←→ 📍 책상 모서리 (120, 160)
  📍 의자 다리 (200, 300)   ←→ 📍 의자 다리 (210, 290)
  ...
```

**방법:**
- ORB, SIFT 특징점 검출
- Descriptor 매칭
- 보통 50~200개 대응점 확보

#### Step 2: 좌표 정규화

**왜 필요한가요?**
```
문제: 카메라마다 초점 거리, 중심점이 다름
      (스마트폰 vs DSLR 카메라)

해결: "표준 카메라"로 변환! 
      → 초점 거리 1, 중심점 (0, 0)
```

**수식:**
```
픽셀 좌표 (u, v) → 정규화 좌표 (x, y)

[x]       [u]
[y] = K^{-1} * [v]
[1]       [1]

K: 카메라 내부 파라미터
```

**예시:**
```
카메라 K:
  fx = 600 (수평 초점 거리)
  fy = 600 (수직 초점 거리)
  cx = 400 (중심 x)
  cy = 300 (중심 y)

픽셀 (400, 300) → 정규화 (0, 0) ✓ (이미지 중심)
픽셀 (1000, 300) → 정규화 (1, 0) ✓ (오른쪽 1 unit)
```

#### Step 3: 5-Point Algorithm으로 E 추정

**왜 최소 5개 점이 필요한가요?**
```
E의 자유도 = 5
  - 카메라 회전 (Rotation): 3개 (roll, pitch, yaw)
  - 이동 방향 (Translation): 2개 (크기는 모름!)
  
→ 최소 5개 제약식 필요
→ 최소 5개 대응점 필요
```

**실제로는...**
```
5개만 쓰면: 노이즈에 약함 😢
보통: 50~200개 사용 + RANSAC! 💪
```

#### Step 4: RANSAC으로 Outlier 제거

**문제 상황:**
```
매칭 결과:
  ✅ Good: 180개 (정확한 대응)
  ❌ Bad: 20개 (잘못된 대응 - outlier)
```

**RANSAC 원리:**
```
┌──────────────────────────────┐
│ RANSAC 반복 (100번)          │
├──────────────────────────────┤
│ 1. 무작위로 5개 점 선택       │
│ 2. E 계산                    │
│ 3. 전체 점 검증               │
│    (에피폴라 오차 < 1 픽셀?) │
│ 4. Inlier 개수 세기          │
└──────────────────────────────┘
           ↓
    가장 많은 Inlier를 가진 E 선택!
```

**OpenCV 코드:**
```cpp
cv::Mat E = cv::findEssentialMat(
    points1_norm,  // 정규화된 점들
    points2_norm,
    cv::Mat::eye(3, 3, CV_64F),  // Identity (정규화됨)
    cv::RANSAC,    // RANSAC 사용
    0.999,         // 99.9% 신뢰도
    1.0,           // 임계값 (픽셀)
    inliers        // 출력: inlier 마스크
);
```

### 4. E에서 R, t 복원하기

#### 놀라운 사실: E는 4개의 해를 가집니다!

**왜 4개나?**
```
E를 분해하면:
  R: 2가지 가능 (R1 or R2)
  t: 2가지 가능 (+t or -t)
  
→ 2 × 2 = 4가지 조합!
```

**4가지 해:**
```
1. (R1, +t) - 카메라가 앞으로 이동
2. (R1, -t) - 카메라가 뒤로 이동
3. (R2, +t) - 다른 회전 + 앞으로
4. (R2, -t) - 다른 회전 + 뒤로
```

####  Cheirality Check - 올바른 해 선택

**원리:** 3D 점이 **두 카메라 앞**에 있어야 함!

**비유:**
```
상황: 책상 위 물체를 카메라로 찍음

올바른 해: 물체가 카메라 앞에 있음 (depth > 0) ✅
틀린 해: 물체가 카메라 뒤에 있음 (depth < 0) ❌
```

**체크 방법:**
```
각 해마다:
  1. 3D 점들 삼각측량
  2. depth가 양수인 점 개수 세기
  3. 가장 많은 점이 앞에 있는 해 선택!
```

**OpenCV가 자동으로 해줌:**
```cpp
int good_points = cv::recoverPose(
    E,              // Essential Matrix
    points1, points2,
    R, t,           // 출력: 올바른 R, t
    inliers         // 출력: 유효한 점들
);
```

### 5. 초기 3D 맵 생성 - 삼각측량(Triangulation)

#### 문제: 어떻게 2D → 3D로 만들까?

**비유:**
```
👁️────────────→ 📦
카메라 1          물체 (어디쯤?)

안 됨! 거리를 모름 😢

👁️────────────→ 📦 ←────────────👁️
카메라 1                        카메라 2

됨! 두 선의 교점 = 3D 위치! 😊
```

**수식:**
```
카메라 1: x1 = K * [I | 0] * X
카메라 2: x2 = K * [R | t] * X

두 식을 풀면 → X (3D 점) 계산!
```

**OpenCV 코드:**
```cpp
// 투영 행렬 구성
cv::Mat P1 = K * cv::Mat::eye(3, 4, CV_64F);  // [I|0]
cv::Mat P2(3, 4, CV_64F);
R.copyTo(P2.rowRange(0, 3).colRange(0, 3));
t.copyTo(P2.rowRange(0, 3).col(3));
P2 = K * P2;  // K*[R|t]

// 삼각측량
cv::Mat points4D;
cv::triangulatePoints(P1, P2, points1, points2, points4D);

// 동차 좌표 → 3D
for (int i = 0; i < points4D.cols; i++) {
    cv::Mat x = points4D.col(i);
    x /= x.at<float>(3);  // 정규화
    
    // Depth 체크
    if (x.at<float>(2) > 0) {  // 카메라 앞에 있음
        points3D.push_back(cv::Point3f(x.at<float>(0), 
                                       x.at<float>(1), 
                                       x.at<float>(2)));
    }
}
```

### 6. 가장 큰 문제: 스케일 모호성(Scale Ambiguity)

#### 핵심 문제

**수식:**
```
E = t^ * R
E = (2*t)^ * R  ← 똑같음!
E = (10*t)^ * R ← 이것도 똑같음!

왜? 투영 방정식에서 깊이와 이동이 곱해져서 상쇄됨
```

**현실에서:**
```
실제: 1m 이동
추정: ... 몇 m인지 모름! 😱

대신:
  - 방향은 정확히 알 수 있음 ✅
  - 비율도 알 수 있음 ✅
  - 절대 크기는 모름 ❌
```

**예시로 이해:**
```
Case 1: 카메라가 1m 이동, 물체 5m 앞
Case 2: 카메라가 10m 이동, 물체 50m 앞

→ 이미지에서 똑같이 보임!
→ 구분 불가능!
```

**해결 방법:**
```
1. IMU 센서 사용 (Phase 4)
   - 실제 가속도 측정 → 실제 거리 계산
   
2. Stereo 카메라
   - 카메라 간격(baseline)을 알면 절대 거리 계산
   
3. 알려진 물체
   - "이 QR코드는 10cm야" → 스케일 복원
   
4. 일단 ||t|| = 1로 정규화
   - 나중에 다른 정보로 보정
```

### 7. 주의해야 할 특수 상황들

#### Pure Rotation (순수 회전)

**문제:**
```
상황: 제자리에서 고개만 돌림 (t = 0)

E = t^ * R = 0^ * R = 0  (영행렬!)

→ 아무 정보도 없음! 😱
```

**해결:**
```
선택 기준:
  - 평행이동이 충분한 프레임 쌍 선택
  - Baseline > 10% image width
```

#### Degenerate Case (평면 장면)

**문제:**
```
상황: 모든 점이 벽처럼 평면에 있음

E로도...  설명 가능
H(Homography)로도... 설명 가능

→ 어느 게 맞아?? 🤔
```

**해결: ORB-SLAM 방식**
```
동시에 계산:
  - E로 RANSAC
  - H로 RANSAC
  
Inlier 비교:
  RH = inliers_H / total
  RE = inliers_E / total
  
IF RH / (RH + RE) > 0.45:
    평면 장면 → Homography 사용
ELSE:
    일반 장면 → Essential 사용
```

## 💡 핵심 개념 정리

### Epipolar Constraint (에피폴라 제약)

**수식:**
```
p2^T * E * p1 = 0
```

**직관적 의미:**
```
                에피폴라 선
카메라 1의 점 ─────────────→ 카메라 2에서
                              이 선 위에만 존재!
```

**효과:**
```
Before: 640×480 = 307,200 위치 탐색
After: 640 위치만 탐색 (480배 빠름!)
```

###  Normalized Coordinates (정규화 좌표)

**왜 필요?**
```
문제: 카메라마다 초점 거리, 센서 크기 다름
해결: 표준 카메라로 변환 (focal length = 1)
```

**변환:**
```
픽셀 → 정규화:  p_norm = K^{-1} * p_pixel
정규화 → 픽셀:  p_pixel = K * p_norm
```

### 질문 1: Essential vs Fundamental
**Q:** Essential Matrix와 Fundamental Matrix의 차이는?

**A:**
```
Essential (E):
  - 정규화 좌표 사용
  - 캘리브레이션 필요 (K 알아야 함)
  - p_norm^T * E * p_norm = 0
  
Fundamental (F):
  - 픽셀 좌표 직접 사용
  - 캘리브레이션 불필요
  - p_pixel^T * F * p_pixel = 0
  - F = K2^{-T} * E * K1^{-1}
```

### 질문 2: 5개 점
**Q:** 왜 최소 5개 점이 필요한가요?

**A:**
```
E의 자유도 = 5
  - 회전 (R): 3 DoF (roll, pitch, yaw)
  - 이동 방향 (t): 2 DoF (크기는 모호)
  
→ 5개 제약이 필요
→ 각 대응점당 1개 제약
→ 최소 5개 대응점!
```

### 질문 3: 스케일 모호성
**Q:** 왜 이동 거리의 절대값을 모르나요?

**A:**
```
E = t^ * R
E = (10*t)^ * R  ← 똑같음!

왜냐면:
  투영: x = (1/Z) * [X, Y, Z]^T
  Z와 t가 곱해지면서 상쇄
  
해결:
  - IMU로 실제 거리 측정
  - Stereo로 baseline 활용
  - 일단 ||t|| = 1로 정규화
```

### 질문 4: Pure Rotation
**Q:** 제자리에서 고개만 돌리면 왜 문제인가요?

**A:**
```
t = 0 (이동 없음)
E = 0^ * R = 0 (영행렬)

→ 에피폴라 구조 사라짐
→ E 추정 불가능

해결: 충분히 움직인 프레임 쌍 선택!
```

   - 3D 정보 없이 시작
   - 첫 두 프레임만으로 시작 가능

2. **Essential Matrix (E)**
   - 두 카메라 관계를 담은 3×3 행렬
   - E = t^ * R
   - 에피폴라 제약: p2^T * E * p1 = 0

3. **5-Point + RANSAC**
   - 최소 5개 점으로 E 추정 가능
   - 실전에서는 50~200개 + RANSAC

4. **4가지 해 → Cheirality Check**
   - E를 분해하면 4가지 (R, t) 조합
   - Depth > 0인 점이 많은 해 선택

5. **스케일 모호성 - 가장 큰 한계**
   - 이동 **방향**은 정확
   - 이동 **크기**는 모호
   - ||t|| = 1로 정규화
   - Week 3 (PnP)에서 해결! 🚀
