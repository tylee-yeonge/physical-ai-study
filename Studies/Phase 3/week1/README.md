## 🌟 시작하기 전에

### Visual Odometry가 뭐죠?

**쉬운 비유:**
차를 운전할 때 앞 유리창(카메라)만 보면서 "아, 내가 100m 정도 앞으로 갔구나", "왼쪽으로 5도 정도 돌았네"를 파악하는 것과 같습니다.

**정식 정의:**
Visual Odometry(VO)는 **연속적인 카메라 이미지**만 보고 카메라(=로봇/차량)가 **얼마나, 어느 방향으로 움직였는지** 계산하는 기술입니다.

**왜 필요한가요?**
- GPS가 안 되는 곳 (실내, 터널, 지하)
- 정밀한 위치 추정이 필요한 곳 (로봇, 드론)
- 저렴한 센서로 위치 파악 (카메라만 있으면 됨!)

## 📚 핵심 개념 자세히 알아보기

### 1. VO와 SLAM - 뭐가 다른가요?

**간단 비유:**
- **VO**: 눈 가리고 걷기 - 계속 앞만 보고 걸어감 (오차 누적됨)
- **SLAM**: 지도 그리며 걷기 - 전에 왔던 곳 기억하고 보정함

| 구분 | Visual Odometry | SLAM |
|------|----------------|------|
| **하는 일** | "지금 얼마나 움직였어?" | "내가 어디 있고, 주변 지도는?" |
| **범위** | 로컬 (최근 몇 프레임) | 전역 (전체 경로) |
| **Loop Closure** | ❌ 없음 | ✅ 있음 - "어? 여기 전에 왔었네!" |
| **오차 누적** | 계속 쌓임 (드리프트) | Loop로 보정됨 |
| **계산량** | 가벼움 | 무거움 |
| **메모리** | 적음 (최근 것만) | 많음 (전체 지도) |

**실제 예시:**
- 100m 걸어가기
  - **VO**: "10m → 10m → ... → 10m" (마지막엔 105m가 될 수도)
  - **SLAM**: "10m → ... → 어? 출발점이다! 전체 100m 맞네" (보정!)

**둘의 관계:**
SLAM = **VO (프론트엔드)** + **Loop Closure + 최적화 (백엔드)**

### 2. VO 파이프라인 - 단계별로 이해하기

VO는 다음 6단계로 작동합니다:

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│  1. 이미지    │ → │ 2. 특징점    │ → │ 3. 매칭/     │
│    입력      │   │    검출      │   │    추적      │
└─────────────┘   └─────────────┘   └─────────────┘
                                            ↓
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│  6. 포즈     │ ← │ 5. 최적화     │ ← │ 4. 모션      │
│    출력      │   │  (선택)      │   │    추정      │
└─────────────┘   └─────────────┘   └─────────────┘
```

#### 각 단계 자세히 설명

**1단계: 이미지 입력**
```
📷 카메라에서 사진을 연속으로 찍습니다
예: 초당 30장 (30 FPS)
```

**2단계: 특징점 검출**
```
🎯 이미지에서 "특별한 점" 찾기
예: 모서리, 코너 같은 곳
    (벽의 평평한 부분은 별로, 책상 모서리는 좋음!)
    
사용 알고리즘: FAST, ORB
결과: 200~500개 특징점
```

**3단계: 매칭/추적**
```
🔗 이전 이미지의 점과 현재 이미지의 점 연결하기
예: "이전에 책상 모서리였던 점이 지금은 여기 있네!"
    
방법 1: Optical Flow (Lucas-Kanade) - 빠름
방법 2: Descriptor 매칭 - 정확함
```

**4단계: 모션 추정**
```
📐 대응점들로 카메라가 얼마나 움직였는지 계산
예: "오른쪽으로 0.5m, 위로 2도 회전"
    
방법:
  - 2D-2D (Essential Matrix) - 초기화용
  - 3D-2D (PnP) - 추적용 ⭐
```

**5단계: Local 최적화 (선택)**
```
✨ 더 정확하게 다듬기
예: "음, 조금 더 정확히는 0.48m네"
    
방법: Bundle Adjustment
```

**6단계: 포즈 출력**
```
📍 최종 카메라 위치 & 방향
결과: [회전 R, 이동 t]
```

### 3. VO의 종류 - 카메라에 따라 달라요

#### 🎥 Monocular VO (단안 - 카메라 1개)

**장점:**
- ✅ 간단! 스마트폰 카메라 하나면 됨
- ✅ 저렴! 추가 장비 불필요
- ✅ 가벼움! 드론, 소형 로봇에 적합

**단점:**
- ⚠️ **스케일 모호성** - 가장 큰 문제!
  ```
  질문: 1m 앞에 있는 큰 물체 vs 10m 앞에 있는 작은 물체?
  답: 똑같이 보임! 😱
  → 이동 거리도 1m인지 10m인지 모름
  ```

**사용 예:** 드론, AR 앱, 실내 청소 로봇

#### 🎥🎥 Stereo VO (스테레오 - 카메라 2개)

**장점:**
- ✅ **스케일 복원!** - 실제 거리 알 수 있음
  ```
  원리: 사람 두 눈처럼 시차로 거리 측정
  예: 왼쪽 카메라에서 10cm, 오른쪽에서 8cm → 계산으로 정확한 거리!
  ```
- ✅ 안정적인 depth 추정

**단점:**
- ⚠️ 무겁고 비쌈 (카메라 2개 + 동기화)
- ⚠️ 캘리브레이션 필요

**사용 예:** 자율주행차, 야외 로봇

#### 🎥🌈 RGB-D VO (카메라 + Depth 센서)

**장점:**
- ✅ 직접 depth 제공! (측정 불필요)
- ✅ 가장 빠른 처리

**단점:**
- ⚠️ 실외/햇빛에 약함 (적외선 방식)
- ⚠️ 거리 제한 (보통 5m 이내)

**사용 예:** Kinect, RealSense, 실내 AR/VR

### 4. SLAM에서 VO의 역할

**VINS-Mono 같은 VIO 시스템:**
```
┌──────────────────────────────────┐
│         VINS-Mono SLAM           │
├──────────────────────────────────┤
│  프론트엔드 (VO)                    │
│  - 특징점 추적                      │
│  - 포즈 초기 추정   ← 우리가 배우는 것! │
├──────────────────────────────────┤
│  백엔드 (Optimization)             │
│  - Bundle Adjustment             │
│  - Loop Closure                  │
│  - Marginalization               │
└──────────────────────────────────┘
```

**AMR(자율주행 로봇)에서:**
- Wheel Odometry (바퀴로 거리 측정) ≈ Visual Odometry (카메라로 거리 측정)
- 둘 다 오차 누적됨 → IMU, GPS 등과 융합 필요

## 💡 꼭 이해해야 할 핵심 개념

### 스케일 모호성 (Scale Ambiguity)

**문제 상황:**
```
실제: 1m 이동
카메라가 본 것: "뭔가 이동했는데... 1m? 10m? 100m? 몰라!"
```

**왜 이런 일이?**
```
카메라는 "비율"만 볼 수 있습니다.
예: 물체가 절반 크기로 보임
    → 2배 멀어짐? 물체가 실제로 작아짐? 구분 못함!
```

**해결 방법:**
1. **IMU 사용** (Phase 4에서 배울 VIO)
   - 가속도로 실제 이동 거리 측정
   
2. **스테레오 카메라**
   - 두 카메라 간격(baseline)으로 실제 거리 계산

3. **알려진 물체 크기**
   - "이 QR코드는 10cm야" → 스케일 보정

### 드리프트 (Drift)

**비유:** 눈 감고 100걸음 걷기
```
1걸음: 1m (목표) → 실제 0.99m (1% 오차)
100걸음 후: 100m (목표) → 실제 99m?
아니요! 오차도 방향이 있어서 더 틀어질 수 있음 😅
```

**VO에서의 드리프트:**
```
프레임 1→2: 0.1m (오차 1mm)
프레임 2→3: 0.1m (오차 1mm)
...
프레임 100개 후: 오차가 수십 cm로 커짐!
```

**원인:**
- 특징점 매칭 오차
- 모션 추정 오차
- 이미지 노이즈

**해결:**
- **SLAM의 Loop Closure!** - "출발점 돌아왔네? 전체 보정!"

## 🔍 자체 점검 - 이해했는지 확인!

### 질문 1: VO vs SLAM
**Q:** 친구가 "VO랑 SLAM이랑 뭐가 다른데?"라고 물어봤어요. 한 문장으로 설명한다면?

**A:** "VO는 앞만 보고 걷는 거고, SLAM은 지도도 그리면서 길 잃으면 되돌아가서 보정하는 거야!"

### 질문 2: 스케일 모호성
**Q:** Monocular VO에서 "1m 이동했다"고 추정했는데, 실제로는 얼마나 이동했을까요?

**A:** 모릅니다! 1m일 수도, 10m일 수도, 0.1m일 수도 있어요. 카메라는 "비율"만 볼 수 있으니까요.

### 질문 3: VO 파이프라인
**Q:** VO에서 가장 시간이 많이 걸리는 단계는?

**A:** **특징점 검출 & 매칭**입니다. 매 프레임마다 수백 개 특징점을 찾고 매칭해야 하니까요!

### 질문 4: 실전 활용
**Q:** 실내 청소 로봇에는 어떤 VO가 적합할까요?

**A:** **Monocular** 또는 **RGB-D**가 좋습니다. 실내라서 GPS 안 되고, 스케일은 바퀴 센서나 IMU로 보정 가능하니까요!

## 🎯 이번 주 핵심 요약

1. **VO = 카메라만으로 위치 추정**
   - 연속 이미지 → 움직임 계산
   
2. **VO ≠ SLAM**
   - VO: 로컬, 오차 누적
   - SLAM: 전역, Loop Closure로 보정

3. **Monocular의 숙명: 스케일 모호성**
   - 비율은 알지만 절대 크기는 모름
   - IMU/Stereo로 해결

4. **VO 파이프라인 6단계**
   - 이미지 → 특징점 → 매칭 → 모션 → 최적화 → 포즈

5. **드리프트는 피할 수 없다**
   - 오차는 누적됩니다
   - SLAM으로 보정 필요
