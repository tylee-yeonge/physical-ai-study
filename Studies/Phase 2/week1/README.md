## 📖 핵심 개념

### 1. 핀홀 카메라 원리

#### 눈과 카메라의 공통점

```
🌍 3D 세계       📷 카메라/눈         🖼️ 이미지/망막
                     
   물체  ──────────→  [ ● ]  ──────────→  상
                      작은 구멍
                    (pinhole/동공)
```

**왜 "핀홀"인가?**

| 구멍 크기 | 장점 | 단점 |
|---------|------|------|
| 큰 구멍 | 밝은 이미지 | 흐릿함 (여러 방향의 빛이 겹침) |
| 작은 구멍 (핀홀) | 선명한 이미지 | 어두움 (빛이 적게 들어옴) |
| 렌즈 사용 | 밝고 선명 | 왜곡 발생 (Week 2) |

**핀홀 = 이상적인 점 크기의 구멍**
- 한 점에서 나온 빛이 이미지의 **한 점**에만 맺힘
- 수학적으로 가장 단순한 모델
- 실제 렌즈는 이 모델에 왜곡(distortion)을 추가

### 2. 좌표계 이해

#### 네 가지 좌표계

```
┌─────────────────────────────────────────────────────────────┐
│                        좌표계 흐름                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  🌍 월드 좌표계         📷 카메라 좌표계      🖼️ 이미지 좌표계        │
│  (World Frame)         (Camera Frame)        (Image Frame)  │
│       Pw                     Pc                   p         │
│   [Xw, Yw, Zw]           [Xc, Yc, Zc]          [u, v]       │
│                                                             │
│        │                     │                    │         │
│        │  [R|t] 외부 파라미터   │  K 내부 파라미터       │         │
│        └─────────────────────┘────────────────────┘         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

| 좌표계 | 단위 | 원점 | 용도 |
|--------|------|------|------|
| 월드 좌표계 (World) | 미터 | 임의 (보통 시작점) | 3D 맵 표현 |
| 카메라 좌표계 (Camera) | 미터 | 카메라 중심 | 카메라 기준 3D |
| 정규화 이미지 좌표계 | 무차원 | 광축 교점 | 초점거리 1로 정규화 |
| 픽셀 좌표계 (Pixel) | 픽셀 | 이미지 좌상단 | 실제 이미지 좌표 |

### 2-1. 동차 좌표계 (Homogeneous Coordinates)

#### 왜 필요한가?

일반 좌표계에서 **이동(translation)**은 덧셈이고, **회전/스케일**은 곱셈입니다:

```
회전+이동 = R · P + t    ← 곱셈과 덧셈이 섞여 있음
```

이러면 변환을 **연쇄(chain)**할 때 매우 불편합니다:

```
1차 변환: P₁ = R₁ · P + t₁
2차 변환: P₂ = R₂ · P₁ + t₂ = R₂ · (R₁ · P + t₁) + t₂
3차 변환: ...점점 복잡해짐
```

동차 좌표를 쓰면 **모든 변환이 행렬 곱셈 하나**로 통일됩니다:

```
P₂ = T₂ · T₁ · P    ← 행렬을 계속 곱하면 됨
```

#### 핵심 아이디어: 차원을 하나 늘린다

일반 좌표에 **1을 붙여서** 차원을 하나 늘립니다:

```
2D:  (x, y)       →  (x, y, 1)
3D:  (x, y, z)    →  (x, y, z, 1)
```

#### 이동이 곱셈으로 바뀌는 원리

일반 좌표에서 점 `(x, y)`를 `(tx, ty)`만큼 이동하려면:

```
x' = x + tx    ← 덧셈
y' = y + ty
```

동차 좌표에서는 행렬 곱셈 하나로 표현됩니다:

```
| x' |   | 1  0  tx |   | x |
| y' | = | 0  1  ty | * | y |
| 1  |   | 0  0  1  |   | 1 |
```

직접 계산하면:
- x' = 1·x + 0·y + tx·1 = x + tx ✓
- y' = 0·x + 1·y + ty·1 = y + ty ✓

**덧셈이 행렬 곱셈으로 변환되었습니다!**

#### 스케일 불변성 (가장 중요한 성질)

동차 좌표에서는 **전체에 같은 수를 곱해도 같은 점**입니다:

```
(3, 5, 1) = (6, 10, 2) = (9, 15, 3) = (30, 50, 10)
```

일반 좌표로 돌아갈 때는 **마지막 값으로 나누면** 됩니다:

```
(6, 10, 2)   → (6/2, 10/2)   = (3, 5)
(30, 50, 10) → (30/10, 50/10) = (3, 5)
```

#### 카메라 투영에서의 활용

투영 과정을 동차 좌표로 쓰면 **한 번의 행렬 곱**으로 표현됩니다:

```
| u·Zc |                   | Xw |
| v·Zc | = K · [R | t]  ·  | Yw |
|  Zc  |    (3×3)(3×4)      | Zw |
                            |  1 |
```

결과 `(u·Zc, v·Zc, Zc)`는 동차 좌표이므로, **Zc로 나누면** 픽셀 좌표 `(u, v)`를 얻습니다.
코드에서 `x_norm = Xc / Zc`가 바로 **동차 좌표 → 일반 좌표 변환**입니다.

#### 일반 좌표 vs 동차 좌표 비교

| 항목 | 일반 좌표 | 동차 좌표 |
|------|-----------|-----------|
| 이동 표현 | 덧셈 (별도 연산) | 곱셈 (행렬에 포함) |
| 변환 연쇄 | R₂·(R₁·P + t₁) + t₂ | T₂ · T₁ · P |
| 2D 점 | `(x, y)` | `(x, y, 1)` |
| Z 나누기 | 별도 수행 | 자연스럽게 포함 |

> **한마디로**: 동차 좌표는 "덧셈을 곱셈으로 바꿔서 모든 변환을 행렬 곱 하나로 통일"하는 도구입니다. SLAM, 컴퓨터 비전, 3D 그래픽스 어디서나 사용됩니다.

### 3. 투영 과정 (3D → 2D)

#### Step 1: 월드 → 카메라 (외부 파라미터)

**변환 공식**:
```
Pc = R · Pw + t

또는 동차좌표로:

[Pc]   [R | t] [Pw]
[1 ] = [0 | 1] [1 ]
```

**기억하세요** (Phase 1 Week 5 복습):
- R: 3×3 회전 행렬 (카메라 방향)
- t: 3×1 이동 벡터 (카메라 위치)
- [R|t]: 3×4 외부 파라미터 행렬 (Extrinsic)

**직관적 의미**:
- "월드 좌표를 카메라가 보는 기준으로 바꾸기"
- 카메라가 회전하면 → R 변화
- 카메라가 이동하면 → t 변화

#### Step 2: 카메라 → 정규화 이미지 (투영)

**핵심 연산: 원근 투영 (Perspective Projection)**

```
       Xc                     Yc
x' = ──────            y' = ──────
       Zc                     Zc
```

**Zc의 의미**:

| 좌표 | 의미 | 설명 |
|------|------|------|
| Xc | 카메라 기준 좌우 위치 | 양수면 오른쪽, 음수면 왼쪽 |
| Yc | 카메라 기준 상하 위치 | 양수면 아래, 음수면 위 |
| **Zc** | **카메라 기준 깊이 (depth)** | 카메라에서 점까지의 거리 |

- Zc > 0: 점이 카메라 **앞**에 있음 (투영 가능)
- Zc ≤ 0: 점이 카메라 **뒤**에 있음 (투영 불가!)

**왜 Zc로 나눌까?**

```
         ☀️ (먼 물체, 큰 Zc)
          \
           \      📷
    ⭐ (가까운 물체, 작은 Zc)
      \
       \
        ──────────────────  이미지 평면
```

- **가까운 물체** (Zc 작음): 이미지에서 크게 보임
- **먼 물체** (Zc 큼): 이미지에서 작게 보임
- Zc로 나누는 것 = **원근감** 표현!

**비유**: 기찻길이 멀리서 만나 보이는 것과 같은 원리

#### Step 3: 정규화 → 픽셀 (내부 파라미터)

**카메라 내부 행렬 K (Intrinsic Matrix)**:

```
     [fx  0  cx]
K =  [0  fy  cy]
     [0   0   1]
```

**왜 이 모양일까? (→ 동차 좌표 활용)**

정규화 좌표 → 픽셀 좌표 변환 공식에는 **곱하기와 더하기**가 섞여 있습니다:

```
u = fx · x' + cx    ← 곱하기 + 더하기
v = fy · y' + cy
```

단순한 2×2 행렬로는 더하기(+cx, +cy)를 표현할 수 없습니다:

```
| u |   | fx  0 |   | x' |    → u = fx·x' (cx를 더할 수 없음!)
| v | = | 0  fy | * | y' |    → v = fy·y'
```

**해결**: 동차 좌표로 차원을 늘리면 행렬 곱셈만으로 더하기까지 표현 가능합니다:

```
| u |   | fx   0   cx |   | x' |
| v | = |  0   fy  cy | * | y' |
| 1 |   |  0    0   1 |   |  1 |
```

직접 계산하면:
- u = fx·x' + 0·y' + cx·1 = **fx·x' + cx** ✅
- v = 0·x' + fy·y' + cy·1 = **fy·y' + cy** ✅
- 1 = 0·x' + 0·y' + 1·1 = **1** ✅

**0인 위치의 의미**:

| 위치 | 값 | 이유 |
|------|-----|------|
| K(0,1) = 0 | fx 옆 | x'이 v(세로)에 영향 없음 → x축과 y축이 직교 |
| K(1,0) = 0 | fy 옆 | y'이 u(가로)에 영향 없음 → 같은 이유 |
| K(2,0), K(2,1) = 0 | 아래행 | 세 번째 좌표를 항상 1로 유지 |

> 참고: 카메라 센서가 기울어져 x/y축이 직교하지 않으면 K(0,1) 자리에 **skew** 값이 들어갑니다. 요즘 카메라는 거의 항상 0입니다.

**각 요소의 의미**:

| 파라미터 | 의미 | 단위 | 전형적인 값 |
|---------|------|------|------------|
| fx | X축 초점 거리 | 픽셀 | 500~1500 |
| fy | Y축 초점 거리 | 픽셀 | 500~1500 |
| cx | 주점 X 좌표 | 픽셀 | 이미지 너비/2 근처 |
| cy | 주점 Y 좌표 | 픽셀 | 이미지 높이/2 근처 |

**초점 거리 (Focal Length, f)**:

```
        렌즈/핀홀
           │
           │
    ←──f──→│
           │
           │──────────── 이미지 센서
```

- 물리적 초점 거리(mm)와 픽셀 크기로 계산
- `fx = f_mm / pixel_size_x`
- 클수록 → 좁은 시야각 (망원)
- 작을수록 → 넓은 시야각 (광각)

**주점 (Principal Point, cx, cy)**:

**물리적 의미**:
- **카메라의 광축(optical axis)이 이미지 평면과 만나는 점**
- 카메라가 정면을 바라보는 방향의 중심축이 센서와 교차하는 위치

```
    광축 (Optical Axis)
       ↓
 렌즈   │
  ◎────┼──────────→
       │           
  ─────●─────────  이미지 센서
    주점 (cx, cy)
```

**수학적 역할**:
- 정규화 좌표 → 픽셀 좌표 변환 시 **원점 이동(translation)** 역할
- 정규화 좌표는 (0, 0)이 중심, 픽셀 좌표는 (0, 0)이 좌상단
- (cx, cy)가 두 좌표계를 연결

**이론값 vs 실제값**:

```python
# 이론값 (완벽한 제조 가정)
cx_ideal = image_width / 2   # 예: 640/2 = 320.0
cy_ideal = image_height / 2  # 예: 480/2 = 240.0

# 실제 캘리브레이션 결과
cx_actual = 320.885  # 이론값과 0.885 픽셀 차이
cy_actual = 244.357  # 이론값과 4.357 픽셀 차이
```

**왜 차이가 발생하나?**

```
제조 오차의 원인:

1️⃣ 조립 오차:
   이상적           실제
   렌즈             렌즈
     │               │╱  ← 약간 기울어짐
     │               │
  ───┼───         ───┼── ← 센서가 치우침
   센서             센서

2️⃣ 센서 정렬:
  렌즈 중심         렌즈 중심
      ●                ●
      │                │ \
  ┌───┼───┐        ┌───┼──╲┐
  │   ●   │        │    ●   │ ← 광축이 벗어남
  └───────┘        └─────────┘
```

**실제 카메라 예시**:

| 카메라 | 해상도 | 이론 cx | 실제 cx | 이론 cy | 실제 cy | 오차 |
|--------|--------|---------|---------|---------|---------|------|
| 웹캠 | 640×480 | 320.0 | 320.885 | 240.0 | 244.357 | 4.4px |
| iPhone | 1920×1080 | 960.0 | 962.3 | 540.0 | 538.1 | 2.8px |
| RealSense | 640×480 | 320.0 | 320.885 | 240.0 | 244.357 | 4.4px |

→ 고급 카메라도 1~5픽셀 정도 차이 발생!

**오차의 영향**:

```python
# 잘못된 주점 사용 예시
# 실제: cx = 320, 잘못 사용: cx = 330

# 이미지 중심 (320, 240) 역투영 시:
x'_wrong = (320 - 330) / fx = -10/fx  # ❌ 왼쪽으로 치우침
x'_correct = (320 - 320) / fx = 0     # ✅ 정면
```

| 오차 크기 | 영향 | SLAM 결과 |
|---------|------|-----------|
| < 1 픽셀 | 미미 | 무시 가능 |
| 1-5 픽셀 | 중간 | 재투영 오차 증가 |
| > 5 픽셀 | 심각 | Bundle Adjustment 실패 |
| > 10 픽셀 | 치명적 | SLAM 시스템 붕괴 |

**캘리브레이션의 중요성**:

- ❌ 이론값 사용: 재투영 오차 2~5 픽셀 (나쁨)
- ✅ 캘리브레이션: 재투영 오차 < 0.5 픽셀 (좋음)
- Week 2에서 체커보드 패턴을 이용한 정확한 측정 방법 학습

**fx ≠ fy인 이유**:
- 이상적: fx = fy (정사각형 픽셀)
- 실제: 센서 픽셀이 완벽한 정사각형이 아닐 수 있음
- 대부분 거의 같지만, 정밀 작업에서는 구별

**최종 픽셀 좌표**:

```
u = fx · x' + cx = fx · (Xc/Zc) + cx
v = fy · y' + cy = fy · (Yc/Zc) + cy
```

### 3-1. 🔍 K는 왜 카메라마다 고유할까?

#### K 행렬의 특성

**핵심 개념**: K 내부 파라미터는 **카메라 하드웨어의 고유 특성**을 나타냅니다.

```
🎥 같은 모델 카메라라도 각 개체마다 K가 다릅니다!
```

#### 카메라마다 K가 다른 이유

**1. 렌즈 특성 차이**

| 요소 | 영향 | 예시 |
|------|------|------|
| **물리적 초점 거리 (f_mm)** | fx, fy 결정 | 표준: 50mm, 광각: 24mm, 망원: 200mm |
| **렌즈 타입** | FOV 크기 | 어안렌즈 vs 망원렌즈 |
| **줌 설정** | fx, fy 변화 | 줌 인/아웃 시 초점 거리 변경 |

**2. 센서 특성 차이**

| 요소 | 영향 | 예시 |
|------|------|------|
| **센서 크기** | fx, fy 스케일 | 풀프레임(36×24mm) vs 스마트폰(~6×5mm) |
| **센서 해상도** | 픽셀 크기 | 12MP vs 48MP |
| **픽셀 피치** | fx, fy 계산 | 픽셀 간격 2μm vs 5μm |

**3. 제조 공정 오차**

```
   이상적인 조립         실제 조립
   
      렌즈                렌즈
        │                  │╱  ← 약간 기울어짐
        │                  │
    ────┼────          ────┼─── ← 센서가 약간 치우침
      센서                센서
        ↑                   ↑
    광축이 정중앙        광축이 중심에서 벗어남
   (이론적 cx, cy)     (실제 cx, cy)
```

- **조립 오차**: 렌즈와 센서의 정렬이 완벽하지 않음
- **개체 편차**: 같은 공장, 같은 날 만든 카메라도 미세하게 다름
- **결과**: cx, cy가 이론값(width/2, height/2)에서 벗어남

#### fx와 시야각(FOV)의 관계

**FOV 계산 공식**:
```
FOV_horizontal = 2 × arctan(width / (2 × fx))
FOV_vertical   = 2 × arctan(height / (2 × fy))
```

**왜 2가 두 번 나올까? (기하학적 유도)**:

FOV는 이미지 양쪽 끝을 잇는 **전체 각도**입니다. 직각삼각형의 `atan`으로 구하려면 **절반으로 나눠서** 계산해야 합니다:

```
        ← ────── W (이미지 전체 폭) ────── →
        ┌──────────────┬──────────────┐  이미지 평면
        │              │              │
        │     W/2      │     W/2      │
        │              │              │
        └──────────────┼──────────────┘
                 \     │     /
                  \  θ │ θ  /       θ = 반쪽 각도 (half-angle)
                   \   │   /
                    \  │  /
              fx     \ │ /    fx
                      \│/
                       ● 카메라 중심
```

- **반쪽 각도 θ** = `atan( (W/2) / fx )` = `atan( W / (2×fx) )` ← 분모의 `2×fx`는 W를 절반으로 나누는 효과
- **전체 FOV** = `2 × θ` ← 바깥의 `2×`는 반쪽 각도를 전체로 복원

코드에서 `* 180.0 / CV_PI`는 라디안 → 도(degree) 변환입니다.

**비교표**:

| 카메라 종류 | fx (픽셀) | 이미지 너비 | FOV (도) | 특성 |
|-----------|----------|------------|----------|------|
| 어안 렌즈 | 200 | 640 | ~140° | 초광각, 심한 왜곡 |
| 스마트폰 | 600 | 640 | ~60° | 광각 |
| 웹캠 | 800 | 640 | ~45° | 표준 |
| DSLR 표준 | 1200 | 640 | ~30° | 좁은 시야 |
| DSLR 망원 | 2400 | 640 | ~15° | 매우 좁음, 줌 인 |

**직관적 이해**:
- fx **크다** → FOV **작다** → 망원 효과 (멀리 크게)
- fx **작다** → FOV **크다** → 광각 효과 (넓게 작게)

| 상황 | K 변화? | 이유 |
|------|---------|------|
| 카메라 이동 | ❌ 변화 없음 | 외부 파라미터 [R\|t]만 변함 |
| 장면 변경 | ❌ 변화 없음 | 카메라 하드웨어는 동일 |

### 3-2. 🔄 역투영 (Back-projection)

#### 역투영이란?

**역투영**은 투영의 반대 과정입니다:

```
투영 (Projection):      3D 점 → 2D 픽셀
역투영 (Back-projection): 2D 픽셀 → 3D 광선
```

**중요**: 역투영으로는 **완전한 3D 점을 복원할 수 없습니다!**

#### 왜 3D 점이 아니라 3D 광선인가?

**깊이 정보 손실 문제**:

```
    여러 3D 점들이 같은 픽셀로 투영됨
    
카메라 ●───────→────→────→
         \     │    │    │
          \    P1   P2   P3  (모두 다른 깊이)
           \   │    │    │   Zc=1m, 2m, 5m
            \  │    │    │
             \ │    │    │
              \│____│____│
               ●
            같은 픽셀!
```

**한 픽셀로 투영되는 3D 점은 무수히 많습니다**:
- 카메라에서 출발한 **광선 위의 모든 점**이 그 픽셀로 투영됨
- 역으로는 **깊이(depth, Zc)**를 알 수 없음
- 하지만 **광선의 방향**은 복원 가능!

#### 역투영 공식

**Step 1**: 투영 공식을 역으로 풀기

투영 공식:
```
u = fx · (Xc/Zc) + cx
v = fy · (Yc/Zc) + cy
```

역으로 풀면:
```
(u - cx) / fx = Xc/Zc  →  x' (정규화 X 좌표)
(v - cy) / fy = Yc/Zc  →  y' (정규화 Y 좌표)
```

**Step 2**: 정규화 좌표 계산

```python
x' = (u - cx) / fx
y' = (v - cy) / fy
```

**Step 3**: 3D 광선 방향 구성

카메라 좌표계에서 3D 점은:
```
Pc = [Xc, Yc, Zc] = Zc · [x', y', 1]
```

여기서 `Zc`는 알 수 없는 깊이이므로, **Zc = 1로 가정**한 광선:

```python
ray_direction = [x', y', 1]
```

보통 단위 벡터로 정규화:

```python
ray_normalized = ray_direction / ||ray_direction||
```

#### 역투영 공식 요약

```
입력: 픽셀 (u, v), 내부 파라미터 K

x' = (u - cx) / fx
y' = (v - cy) / fy
ray = [x', y', 1]  (정규화 필요)

출력: 3D 광선 방향 (단위 벡터)
```

#### Python 구현

```python
def back_project(pixel, K):
    """
    2D 픽셀에서 3D 광선 방향 복원
    
    Args:
        pixel: [u, v] 픽셀 좌표
        K: 내부 파라미터 행렬
    
    Returns:
        ray_direction: 정규화된 3D 방향 벡터
    """
    fx, fy = K[0, 0], K[1, 1]
    cx, cy = K[0, 2], K[1, 2]
    u, v = pixel
    
    # 정규화 좌표 계산
    x_normalized = (u - cx) / fx
    y_normalized = (v - cy) / fy
    
    # 광선 방향 (카메라 좌표계, Zc=1 가정)
    ray = np.array([x_normalized, y_normalized, 1.0])
    
    # 단위 벡터로 정규화
    ray_normalized = ray / np.linalg.norm(ray)
    
    return ray_normalized
```

#### 특수한 경우들

**이미지 중심 픽셀**:

```python
pixel_center = [cx, cy]  # 예: [320, 240]

# 역투영:
x' = (cx - cx) / fx = 0
y' = (cy - cy) / fy = 0

ray = [0, 0, 1]  # Z축 방향 (카메라 정면)
```

→ 이미지 중심은 카메라가 **정면**을 바라보는 방향

**이미지 모서리 픽셀**:

```python
pixel_corner = [0, 0]  # 좌상단

# 역투영:
x' = (0 - 320) / 500 = -0.64
y' = (0 - 240) / 500 = -0.48

ray = [-0.64, -0.48, 1]
```

→ **음의 X**: 카메라 기준 왼쪽  
→ **음의 Y**: 카메라 기준 위쪽

#### 투영 ↔ 역투영 일관성

역투영을 검증하는 방법:

```python
# 1. 원본 3D 점
P_original = np.array([2, 1, 5])

# 2. 투영 → 픽셀
pixel = project_point(P_original, R, t, K)

# 3. 역투영 → 광선
ray = back_project(pixel, K)

# 4. 원본 점의 방향 계산
direction_original = P_original / np.linalg.norm(P_original)

# 5. 방향이 일치하는지 확인
assert np.allclose(ray, direction_original)  # ✅
```

**핵심**: 역투영으로 복원한 광선은 원본 점의 **방향**과 일치하지만, **거리(깊이)**는 복원 불가!

#### SLAM에서의 활용

**1. Depth 정보와 결합 (RGB-D SLAM)**:

```python
# 역투영으로 방향 구하기
ray = back_project(pixel, K)

# 깊이 센서에서 거리 얻기
depth = depth_sensor.get_depth(pixel)  # 예: 2.5m

# 완전한 3D 점 복원!
P_camera = ray * depth
```

**2. 특징점 추적과 삼각측량 (Triangulation)**:

```
프레임 1:                프레임 2:
카메라1 ●→ ray1          카메라2 ●→ ray2
         \                     /
          \                   /
           \                 /
            \               /
             ●  3D 점 복원!
          (두 광선의 교차점)
```

```python
# 두 프레임에서 같은 점 관측
ray1 = back_project(pixel1, K)  # 카메라1
ray2 = back_project(pixel2, K)  # 카메라2

# 삼각측량으로 3D 위치 복원
P_3d = triangulate(ray1, ray2, R1, t1, R2, t2)
```

**3. 에피폴라 기하학 (Epipolar Geometry)**:

역투영은 에피폴라 선 계산의 기초:
- 카메라1에서 본 픽셀 → 역투영 → 광선
- 이 광선이 카메라2의 이미지에서는 "에피폴라 선"으로 나타남
- SLAM의 특징점 매칭 시 탐색 영역 축소에 활용

#### 역투영 vs 투영 비교

| 항목 | 투영 (Projection) | 역투영 (Back-projection) |
|------|------------------|------------------------|
| 방향 | 3D → 2D | 2D → 3D |
| 입력 | 3D 점 (Xc, Yc, Zc) | 2D 픽셀 (u, v) |
| 출력 | 2D 픽셀 (u, v) | 3D 광선 방향 |
| 정보 손실 | ✅ 깊이 정보 손실 | ❌ 깊이 복원 불가 |
| 유일성 | ✅ 한 3D 점 → 한 픽셀 | ❌ 한 픽셀 → 무한한 3D 점 |
| 핵심 연산 | ÷ Zc (원근 투영) | × Zc (깊이 필요) |

#### 요약

| 항목 | 내용 |
|------|------|
| **복원 가능** | ✅ 광선 방향 |
| **복원 불가** | ❌ 깊이 (거리) |
| **공식** | `ray = [(u-cx)/fx, (v-cy)/fy, 1]` |
| **활용** | 삼각측량, RGB-D 융합, 에피폴라 기하학 |
| **SLAM 의미** | 특징점의 방향 정보, 깊이는 다른 방법으로 추정 |

**핵심 메시지**:
> 역투영은 투영의 역과정이지만, **깊이 정보 손실**로 인해 완전한 3D 점 복원은 불가능합니다.
> 
> 하지만 **광선의 방향**을 알 수 있고, 이는 삼각측량, RGB-D SLAM 등에서 핵심 역할을 합니다!

### 4. 전체 투영 공식

#### 행렬 형태

```
       [u]          [Xw]
   s · [v] = K[R|t] [Yw]
       [1]          [Zw]
                    [1 ]
```

- s: 스케일 팩터 (Zc와 같음)
- K: 3×3 내부 파라미터
- [R|t]: 3×4 외부 파라미터
- 결과: 3×1 동차 좌표 → 나누면 (u, v) 픽셀

#### Python 구현

```python
import numpy as np

def project_point(P_world, R, t, K):
    """
    3D 월드 점을 2D 픽셀로 투영

    Args:
        P_world: 3D 점 [X, Y, Z]
        R: 3x3 회전 행렬
        t: 3x1 이동 벡터
        K: 3x3 내부 파라미터 행렬

    Returns:
        pixel: [u, v] 픽셀 좌표
    """
    # 입력 정규화: 다양한 형태의 입력을 (3,) 1차원 배열로 변환
    # flatten()은 다차원 배열을 1차원으로 평탄화
    # 예: [[1], [2], [3]] (3,1) → [1, 2, 3] (3,)
    #     [[1, 2, 3]] (1,3) → [1, 2, 3] (3,)
    P_world = np.array(P_world).flatten()

    # Step 1: 월드 → 카메라
    # t.flatten(): (3,1) → (3,)로 변환하여 브로드캐스팅 문제 방지
    P_camera = R @ P_world + t.flatten()
    
    # Step 2: 카메라 → 정규화 이미지 (원근 투영)
    x_normalized = P_camera[0] / P_camera[2]
    y_normalized = P_camera[1] / P_camera[2]
    
    # Step 3: 정규화 → 픽셀
    fx, fy = K[0, 0], K[1, 1]
    cx, cy = K[0, 2], K[1, 2]
    
    u = fx * x_normalized + cx
    v = fy * y_normalized + cy
    
    return np.array([u, v])
```

#### 재투영 오차 (Reprojection Error)

**개념**: 3D 점을 이미지에 투영한 위치와 실제 관측 위치의 차이

```
                실제 관측점 ●
                          /
                         / 재투영 오차
                        /
    투영된 점 ○ ←──────
```

**계산**:
```python
def reprojection_error(P_3d, observed_2d, R, t, K):
    """재투영 오차 계산"""
    projected = project_point(P_3d, R, t, K)
    error = np.linalg.norm(projected - observed_2d)
    return error
```

**SLAM에서 중요한 이유**:
- Bundle Adjustment의 비용 함수
- 최적화 목표: 모든 점의 재투영 오차 합 최소화
- 단위: 픽셀 (보통 1픽셀 이하면 좋음)

## 📊 핵심 정리

### 투영 파이프라인

```
3D 월드 점 (Pw)
      │
      │ [R|t] - 외부 파라미터 (카메라 포즈)
      ▼
3D 카메라 점 (Pc)
      │
      │ 원근 투영 (÷Zc)
      ▼
정규화 이미지 점 (x', y')
      │
      │ K - 내부 파라미터 (카메라 고유)
      ▼
2D 픽셀 점 (u, v)
```

### 핵심 공식

| 단계 | 공식 | 의미 |
|------|------|------|
| 외부 변환 | Pc = R·Pw + t | 월드→카메라 |
| 원근 투영 | (x', y') = (Xc/Zc, Yc/Zc) | 3D→2D |
| 내부 변환 | (u, v) = (fx·x'+cx, fy·y'+cy) | 정규화→픽셀 |

### 파라미터 구분

| 구분 | 파라미터 | 특성 | SLAM에서 |
|------|---------|------|---------|
| 내부 (Intrinsic) | K (fx, fy, cx, cy) | 카메라 고유, 불변 | 캘리브레이션으로 사전 측정 |
| 외부 (Extrinsic) | [R \| t] | 카메라 위치/방향, 변화 | 매 프레임 추정 대상 |

## ❓ FAQ

**Q1: 내부 파라미터 K는 언제 바뀌나요?**
A: **대부분 변하지 않습니다.** 같은 카메라, 같은 렌즈, 같은 줌 설정이면 K는 고정값입니다. 한 번 캘리브레이션하면 계속 재사용합니다.

**변하는 경우**:
- 줌 렌즈를 사용하여 초점 거리 변경 시
- 이미지 크기를 리샘플링한 경우 (스케일 조정 필요)
- 다른 카메라를 사용하는 경우
- 카메라에 물리적 충격이나 손상이 발생한 경우

**Q2: fx와 fy가 같지 않으면 문제인가요?**
A: 아닙니다. 정상입니다. 차이가 너무 크면 (예: 10% 이상) 캘리브레이션 오류를 의심해볼 수 있습니다.

**Q3: Zc가 정확히 무엇인가요?**
A: 카메라 좌표계에서의 Z 좌표, 즉 **카메라로부터의 깊이(depth)**입니다. Zc로 나누는 것이 원근감(가까우면 크게, 멀면 작게)을 표현하는 핵심입니다.

**Q4: Zc가 음수면 어떻게 되나요?**
A: 점이 카메라 뒤에 있다는 뜻입니다. 투영 불가! SLAM에서는 이런 점을 제외합니다.

**Q5: 왜 동차좌표를 사용하나요?**
A: 이동(translation)을 행렬 곱셈으로 표현하기 위해서입니다. 일반 좌표에서는 `R·P + t`처럼 곱셈과 덧셈이 섞이지만, 동차 좌표를 쓰면 하나의 행렬 곱 `T·P`로 통일됩니다. K 행렬이 3×3인 것도 같은 이유입니다. 자세한 내용은 위의 **섹션 2-1. 동차 좌표계** 및 **Step 3의 "왜 이 모양일까?"** 를 참조하세요.

**Q6: flatten()은 왜 사용하나요?**
A: 입력 형태를 통일하기 위해서입니다. 사용자가 `[1,2,3]`, `[[1],[2],[3]]`, `[[1,2,3]]` 등 다양한 형태로 입력해도 모두 `[1,2,3]` (shape: (3,))으로 변환하여 연산 오류를 방지합니다.

**Q7: 같은 모델 카메라를 여러 대 사용하면 K가 같나요?**
A: **아니요, 각각 캘리브레이션해야 합니다.** 같은 모델이라도 제조 공정상 미세한 차이가 있어 cx, cy가 달라질 수 있고, fx, fy도 약간 다를 수 있습니다. 정밀도가 중요한 SLAM에서는 각 카메라마다 개별 캘리브레이션이 필수입니다.

**Q8: K 값이 정확하지 않으면 어떤 문제가 생기나요?**
A: **재투영 오차가 커집니다.** 이는 SLAM에서 치명적입니다:
- 잘못된 3D 위치 추정
- Bundle Adjustment 최적화 실패
- 루프 클로저 검출 실패
- 궤적 드리프트 증가

정확한 K가 없다면 SLAM 시스템 전체의 정확도가 떨어집니다.
