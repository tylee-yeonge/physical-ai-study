## 📚 핵심 개념 자세히 알아보기

### 1. VIO 시작 시 모르는 것들

VIO가 처음 시작되면 다음 값들이 **미지수**입니다:

```
┌──────────────────────────────────────────────────────────┐
│              VIO 초기화 시 미지수 목록                      │
├────────────────┬─────────────────────────────────────────┤
│ 미지수          │ 설명                                    │
├────────────────┼─────────────────────────────────────────┤
│ 스케일 s       │ Vision으로 복원한 궤적의 실제 크기       │
│ 중력 방향 g    │ 월드 좌표계에서 중력 벡터의 방향         │
│ 자이로 바이어스 │ 각속도 측정의 일정한 편향 (b_g)          │
│ 가속도 바이어스 │ 가속도 측정의 일정한 편향 (b_a)          │
│ 초기 속도 v_0  │ 시스템 시작 시 이동 속도                 │
│ 각 키프레임 속도│ 슬라이딩 윈도우 내 모든 프레임의 속도    │
└────────────────┴─────────────────────────────────────────┘
```

#### 1.1 스케일 (Scale)

```
단안 카메라의 근본적 한계:

  실제 세계         카메라가 보는 것
  ┌────────┐       ┌────────┐
  │  3m    │       │   ?    │    ← 크기를 모름
  │        │       │        │
  └────────┘       └────────┘

  10cm 상자를 가까이서 본 것 vs 10m 벽을 멀리서 본 것
  → 이미지가 동일할 수 있음!

  Vision-only SfM 결과:
    t_12 = [0.3, 0.0, 0.1]   ← 단위가 없음! (up-to-scale)

  실제로는?
    실제 t_12 = s * [0.3, 0.0, 0.1]  여기서 s = ?
    s = 2.0이면 → 실제 이동 = [0.6, 0.0, 0.2] m
    s = 0.5이면 → 실제 이동 = [0.15, 0.0, 0.05] m
```

#### 1.2 중력 방향 (Gravity Direction)

```
왜 중력 방향을 알아야 하는가?

IMU 가속도계 측정값:
  a_measured = a_actual + R_world_to_body * g + b_a + noise

  여기서 g = [0, 0, -9.81]^T (월드 좌표계)

  정지 상태에서:
    a_measured = R * [0, 0, -9.81]^T + b_a

  → 가속도계는 항상 중력을 측정하고 있음!
  → 중력 방향을 모르면 실제 가속도를 분리할 수 없음!

  중력 방향을 안다면:
    a_actual = a_measured - R * g - b_a
    → 순수 가속도만 추출 가능
    → 이것을 적분해야 속도/위치를 얻음

  중력 크기 (||g|| = 9.81 m/s²)는 알고 있으므로,
  추정할 것은 방향(2 DoF)만!

  ┌─────────────────────────────────────────┐
  │  중력 벡터 g = 9.81 * [gx, gy, gz]^T   │
  │  ||[gx, gy, gz]|| = 1                   │
  │  → 단위 구(unit sphere) 위의 점          │
  │  → 자유도 2 (위도, 경도처럼)             │
  └─────────────────────────────────────────┘
```

#### 1.3 IMU 바이어스 (Bias)

```
바이어스란?

  이상적인 IMU:  측정값 = 실제값
  실제 IMU:     측정값 = 실제값 + 바이어스 + 노이즈

  자이로 바이어스 (b_g):
    ω_measured = ω_actual + b_g + n_g

    b_g ≈ [0.001, -0.002, 0.0005] rad/s  (일반적)

    작아 보이지만...
    1초 후 회전 오차: 0.001 rad ≈ 0.057°
    100초 후: 0.1 rad ≈ 5.7°   ← 상당한 오차!

  가속도 바이어스 (b_a):
    a_measured = a_actual + R*g + b_a + n_a

    b_a ≈ [0.01, -0.005, 0.02] m/s²  (일반적)

    위치 오차 = 0.5 * |b_a| * t²
    10초 후: 0.5 * 0.01 * 100 = 0.5 m   ← 심각!

  초기화에서 b_g를 먼저 추정하는 이유:
    b_g → 회전 추정 오차 → 중력 방향 오차 → b_a 추정 오차 → 위치 발산!

    따라서 초기화 순서:
    1) b_g 추정 (자이로 바이어스 먼저!)
    2) 중력 방향 추정
    3) 스케일, 속도 추정
    4) b_a는 이후 최적화에서 함께 추정
```

#### 1.4 초기 속도 (Initial Velocity)

```
IMU 적분의 초기 조건:

  v(t) = v(0) + ∫[0,t] a(τ) dτ

  v(0)을 모르면?
    → 적분 결과가 전부 틀림!
    → 위치도 틀림!

  예시:
    실제 v(0) = [1.0, 0, 0] m/s (앞으로 걷는 중)

    v(0) = [0,0,0]으로 가정하면:
      1초 후 위치 오차 = 1.0 m
      10초 후 위치 오차 = 10.0 m!

  → 초기 속도도 반드시 추정해야 함
  → 각 키프레임마다 속도가 다를 수 있으므로,
    슬라이딩 윈도우 내 모든 키프레임의 속도를 추정!
```

### 2. 초기화 실패의 심각성

```
초기화 실패 → VIO 전체 실패!

┌─────────────────────────────────────────────────┐
│  VIO 파이프라인:                                 │
│                                                  │
│  [초기화] → [추적] → [최적화] → [루프 클로징]    │
│     ↑                                            │
│     └── 여기서 실패하면 뒤가 전부 무의미!         │
└─────────────────────────────────────────────────┘

초기화 실패 시나리오:

1. 스케일 오류:
   잘못된 s → Vision과 IMU 불일치 → 최적화 발산

   예: 실제 s=2.0인데 s=0.5로 추정
   → IMU가 4배 차이나는 이동을 예측
   → 매 프레임 큰 Residual → 시스템 붕괴

2. 중력 방향 오류:
   잘못된 g → 수평/수직 구분 실패 → 높이 오차 폭발

   5° 중력 방향 오차:
   → 10m 이동 시 높이 오차 ≈ 10 * sin(5°) ≈ 0.87m
   → 로봇이 공중에 뜨거나 바닥에 빠짐

3. 바이어스 오류:
   잘못된 b_g → 회전 드리프트 → 궤적 회전
   잘못된 b_a → 위치 드리프트 → 궤적 발산
```

### 3. VINS-Mono의 Robust 초기화

VINS-Mono는 VIO 초기화의 대표적인 구현입니다:

```
VINS-Mono 초기화 전략:

┌──────────────────────────────────────────────────┐
│  1. 충분한 데이터 수집 (슬라이딩 윈도우 채우기)    │
│     - 10+ 키프레임                                │
│     - 충분한 시차 (parallax > threshold)           │
│                                                   │
│  2. Vision-only SfM (Stage 1)                     │
│     - 5점 알고리즘으로 초기 포즈 추정              │
│     - Up-to-scale 궤적 복원                       │
│                                                   │
│  3. Visual-Inertial Alignment (Stage 2)           │
│     - SfM 결과와 IMU Pre-integration 정렬          │
│     - 스케일 s, 중력 g, 속도 v, 바이어스 b_g 추정  │
│                                                   │
│  4. 검증                                          │
│     - Reprojection error 확인                     │
│     - IMU-Vision 일관성 확인                       │
│     - 실패 시 1로 돌아가서 재시도                  │
│                                                   │
│  5. 성공 시 → 정상 VIO 모드 진입                  │
└──────────────────────────────────────────────────┘

핵심 설계 철학:
  - "초기화에 시간을 투자하더라도 정확하게!"
  - 초기화 실패 → 재시도 (무한 반복 가능)
  - 초기화 성공 조건을 엄격하게 설정
```

#### VINS의 초기화 조건

```
초기화 시도 조건:
  1. 슬라이딩 윈도우에 최소 10개 키프레임
  2. 최신 프레임과 가장 오래된 프레임 사이 충분한 시차
     (parallax > 30 pixel 등)
  3. Feature tracking이 안정적 (최소 50+ 특징점)

초기화 성공 조건:
  1. SfM reprojection error < threshold
  2. Visual-Inertial alignment의 residual이 작음
  3. 추정된 중력 크기가 9.81에 가까움 (±0.5 m/s²)
  4. 추정된 스케일이 양수이고 합리적인 범위

초기화 실패 대응:
  - 가장 오래된 키프레임 제거
  - 새 키프레임 추가
  - 다시 초기화 시도
  - 사용자에게 "움직여달라" 피드백 (일부 구현)
```

### 4. 추정 문제의 수학적 공식화

```
초기화에서 풀어야 할 선형 시스템:

미지수 벡터 x = [s, g(2DOF), v_0, v_1, ..., v_n, b_g]

각 키프레임 쌍 (i, j)에서 제약:

  s * p_j^cam - s * p_i^cam = R_i^T * (v_i * Δt + 0.5*g*Δt² + δp_ij)

  여기서:
  - p_i^cam, p_j^cam: SfM에서 얻은 up-to-scale 위치
  - R_i: 키프레임 i의 회전 (SfM에서 알려짐)
  - δp_ij: IMU Pre-integration으로 얻은 상대 위치
  - Δt: 두 키프레임 사이 시간

이를 선형 최소자승법으로 풀 수 있음:
  A * x = b
  x = (A^T * A)^(-1) * A^T * b

키프레임이 n개이면:
  - 방정식 수: 3(n-1) * 2  (위치 + 속도 제약)
  - 미지수: 1(s) + 2(g) + 3n(v) + 3(b_g) = 3n + 6
  - n >= 4이면 over-determined → 최소자승 해 존재!
```

## 💡 꼭 이해해야 할 핵심 개념

### 왜 Vision-only SfM을 먼저 하는가?

```
전략: "쉬운 것부터 풀자!"

Vision-only SfM (쉬움):
  - 5점 알고리즘 → E/R/t 복원
  - 삼각측량 → 3D 점 복원
  - Bundle Adjustment → 정밀화
  → 방향은 정확, 스케일만 모름

IMU와 결합 (어려움):
  - SfM 결과를 "스케일 없는 참조"로 사용
  - IMU 데이터와 맞춰보면서 스케일 추정
  → 잘 알려진 문제를 먼저 풀고, 그 위에 쌓기!

반대로 하면? (IMU-only → Vision 결합):
  - IMU만으로는 초기 위치를 전혀 모름
  - 바이어스도 모름
  - 수 초 만에 발산
  → 훨씬 어려운 문제!
```

### 충분한 움직임이 필요한 이유

```
정지 상태에서는 초기화 불가능!

이유 1: Vision - 시차(Parallax) 필요
  정지 → 시차 = 0 → 삼각측량 불가 → 3D 복원 불가

이유 2: IMU - 스케일 관측 불가
  정지 → 가속도 = 중력만
  → 스케일과 중력을 분리할 수 없음!

이유 3: 바이어스 - 가관측성(Observability) 문제
  등속 직선 운동 → 가속도 = 0 + 중력 + 바이어스
  → 바이어스와 중력 방향을 구분할 수 없음!

좋은 초기화 움직임:
  ✅ 다양한 방향으로 회전
  ✅ 전후좌우 이동
  ✅ 적어도 2-3초간 충분한 움직임
  ❌ 정지
  ❌ 순수 직선 운동
  ❌ 순수 회전만 (제자리 회전)
```

## 🔍 자체 점검 - 이해했는지 확인!

### Q1. VIO 초기화 시 추정해야 할 4가지 핵심 미지수는?

```
1. 스케일 (s): Vision 궤적의 실제 크기
2. 중력 방향 (g): 월드 좌표계에서 중력 벡터 (2 DoF)
3. 자이로 바이어스 (b_g): 각속도 측정의 편향
4. 초기 속도 (v_0, ..., v_n): 각 키프레임의 속도
```

### Q2. 초기화에 실패하면 왜 VIO 전체가 실패하는가?

```
초기화 결과 (s, g, b_g, v)가 이후 모든 과정의 기반:
- 잘못된 s → Vision/IMU 불일치 → 최적화 발산
- 잘못된 g → 수직 방향 오차 → 높이 발산
- 잘못된 b_g → 회전 드리프트 → 모든 추정값 오염
→ 기초가 틀리면 그 위에 쌓는 모든 것이 무너짐!
```

### Q3. 정지 상태에서 VIO 초기화가 어려운 이유는?

```
1. 시차 없음 → 삼각측량 불가 → SfM 실패
2. 가속도 = 중력만 → 스케일/중력 분리 불가
3. 바이어스와 중력 구분 불가 (관측 가능성 부족)
→ 다양한 방향의 움직임이 필수!
```

### Q4. VINS-Mono가 초기화 실패 시 취하는 전략은?

```
1. 가장 오래된 키프레임 제거
2. 새 키프레임 추가 (계속 추적)
3. 초기화 재시도
4. 성공할 때까지 반복
→ "Robust" 초기화: 실패해도 포기하지 않음!
```
