## 🌟 시작하기 전에

### Pre-integration이 뭐죠?

**쉬운 비유:**
서울에서 부산까지 택시를 타고 갔다고 합시다. 택시 미터기는 매초 거리를 기록합니다.

- **단순 적분 방식**: "서울역에서 출발해서, 1초 후 10m, 2초 후 20m, ..." 이렇게 기록합니다. 그런데 "출발점이 서울역이 아니라 강남역이었어!"라고 바뀌면? **처음부터 전부 다시 계산**해야 합니다.

- **Pre-integration 방식**: "출발점 기준으로 총 400km 남쪽, 방향 175도"라고 기록합니다. 출발점이 바뀌어도? **상대 변위는 그대로**입니다. 출발점만 바꿔서 최종 위치를 바로 구할 수 있습니다.

**정식 정의:**
Pre-integration은 두 키프레임 사이의 IMU 데이터를 **포즈에 독립적인 상대 측정값**(Δp, Δv, ΔR)으로 미리 합치는 기법입니다.

**왜 필요한가요?**
- IMU는 200Hz, 카메라는 20Hz로 주파수 차이가 10배
- 최적화할 때마다 포즈가 바뀌면 IMU 재적분은 비용이 너무 큼
- VIO 시스템의 실시간 처리를 위해 필수적인 기법

## 📚 핵심 개념 자세히 알아보기

### 1. 문제 상황: IMU와 Vision의 주파수 차이

VIO 시스템에서 가장 먼저 마주하는 문제입니다.

```
시간축 →

IMU (200Hz):  ·····································
              ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑
              매 5ms마다 가속도/각속도 측정

Vision (20Hz):↑                   ↑                   ↑
              KF_i                KF_j                KF_k
              50ms 간격으로 이미지 캡처
```

| 센서 | 주파수 | 간격 | 특성 |
|------|--------|------|------|
| IMU | 100~400Hz | 2.5~10ms | 고주파, 단기 정확, 장기 드리프트 |
| Camera | 15~30Hz | 33~67ms | 저주파, 절대 위치, 지연 있음 |

**핵심 질문**: 키프레임 i와 j 사이에 쌓인 IMU 데이터 10~20개를 어떻게 활용할 것인가?

### 2. 접근법 1: 단순 적분 (Naive Integration)

가장 직관적인 방법입니다.

```
KF_i (포즈 알려짐) 에서 시작
  → IMU_1 적분 → 중간 상태 1
  → IMU_2 적분 → 중간 상태 2
  → ...
  → IMU_10 적분 → KF_j 예측값
```

**C++ 코드로 보면:**

```cpp
// 단순 적분: KF_i 포즈에서 시작해서 IMU로 KF_j 예측
void naiveIntegration(
    const Eigen::Vector3d& p_i,     // KF_i 위치
    const Eigen::Vector3d& v_i,     // KF_i 속도
    const Eigen::Quaterniond& q_i,  // KF_i 회전
    const std::vector<IMUData>& imu_data,
    const Eigen::Vector3d& gravity,
    Eigen::Vector3d& p_j,           // KF_j 위치 (출력)
    Eigen::Vector3d& v_j,           // KF_j 속도 (출력)
    Eigen::Quaterniond& q_j)        // KF_j 회전 (출력)
{
    p_j = p_i;
    v_j = v_i;
    q_j = q_i;

    for (const auto& imu : imu_data) {
        double dt = imu.dt;

        // 월드 좌표계에서 가속도 계산
        Eigen::Vector3d acc_world = q_j * imu.acc + gravity;

        // 위치 업데이트
        p_j += v_j * dt + 0.5 * acc_world * dt * dt;

        // 속도 업데이트
        v_j += acc_world * dt;

        // 회전 업데이트
        Eigen::Quaterniond dq(1,
            0.5 * imu.gyro.x() * dt,
            0.5 * imu.gyro.y() * dt,
            0.5 * imu.gyro.z() * dt);
        q_j = (q_j * dq).normalized();
    }
}
```

**이 방법의 치명적 문제:**

```
최적화 반복 1: p_i = [0, 0, 0] → 적분 10개 → p_j 계산
최적화 반복 2: p_i = [0.01, 0, 0] ← 최적화로 p_i 변경!
              → 적분 10개 다시!!! → p_j 재계산
최적화 반복 3: p_i = [0.015, 0, 0.001] ← 또 변경!
              → 적분 10개 또 다시!!! → p_j 재계산
```

비선형 최적화는 보통 10~50회 반복합니다. 매번 IMU 재적분을 하면:
- **계산 비용**: 반복 횟수 × IMU 데이터 수 = 50 × 10 = **500번 적분**
- 키프레임이 여러 개이면 더 심각
- **실시간 처리 불가능!**

### 3. 접근법 2: Pre-integration (핵심!)

**핵심 아이디어**: IMU 적분 결과를 **출발 포즈에 독립적인 형태**로 바꾸자!

```
[기존 방식]
절대 좌표: p_j = p_i + v_i·Δt + R_i·(이중적분) + 0.5·g·Δt²

[Pre-integration 방식]
상대 좌표: Δp_ij = R_i^T · (p_j - p_i - v_i·Δt - 0.5·g·Δt²)
                    ↑ 이 값은 p_i, v_i, R_i와 무관!
```

#### Pre-integrated 측정값 3가지

| 기호 | 의미 | 차원 |
|------|------|------|
| Δp_ij | i 기준 상대 위치 변화 | R³ (3차원 벡터) |
| Δv_ij | i 기준 상대 속도 변화 | R³ (3차원 벡터) |
| ΔR_ij | i 기준 상대 회전 변화 | SO(3) (3×3 회전행렬) |

**직관적 이해:**

```
[절대 좌표 방식 - 내비게이션]
"서울역에서 출발, 동쪽 100m, 남쪽 50m, 왼쪽 회전 30도..."
→ 출발점 바뀌면? 전부 다시 계산!

[상대 좌표 방식 - Pre-integration]
"출발점 기준: 앞으로 100m, 오른쪽 50m, 왼쪽 30도 회전"
→ 출발점 바뀌어도 상대 이동은 그대로!
→ 새 출발점에 상대 이동을 더하기만 하면 끝!
```

### 4. Pre-integration의 동작 원리

#### Step 1: IMU 데이터를 미리 합치기

```
KF_i ← 10개 IMU → KF_j

한 번만 적분해서:
  Δp_ij = 상대 위치 변화
  Δv_ij = 상대 속도 변화
  ΔR_ij = 상대 회전 변화

이 값들은 캐싱됨! (다시 계산 안 해도 됨)
```

#### Step 2: 최적화에서 사용

```
최적화 반복마다:
  p_j_pred = p_i + v_i·Δt + R_i·Δp_ij + 0.5·g·Δt²
                                  ↑ 미리 계산된 값 (재활용!)

  오차 = p_j_pred - p_j_measured
  → 이 오차를 최소화
```

**계산 비용 비교:**

| 방식 | 적분 횟수 | 최적화 비용 |
|------|----------|------------|
| 단순 적분 | 반복 × IMU수 = 500 | O(N × M × K) |
| Pre-integration | IMU수 = 10 (1회) | O(K) |

여기서 N=최적화 반복, M=IMU 데이터 수, K=키프레임 수

### 5. 바이어스 변화 시 처리

"Pre-integration은 바이어스에도 의존하는데, 바이어스가 바뀌면 어쩌죠?"

**해결: 1차 근사 (First-order Approximation)**

```
바이어스가 약간 변할 때 (δb = b_new - b_old):

Δp_corrected ≈ Δp_old + J_p_ba · δb_a + J_p_bg · δb_g
Δv_corrected ≈ Δv_old + J_v_ba · δb_a + J_v_bg · δb_g
ΔR_corrected ≈ ΔR_old · Exp(J_R_bg · δb_g)

J_xx: 자코비안 (Pre-integration 과정에서 같이 계산)
```

**비유:**
- 원래 계산: "바이어스 0.01에서 계산한 상대 이동 = 100m"
- 바이어스 변경: "바이어스가 0.012로 바뀌었다"
- 1차 보정: "상대 이동 ≈ 100m + 기울기 × 0.002 = 100.5m"
- **재적분 없이** 빠르게 보정!

```cpp
// 바이어스 변화에 따른 1차 보정
void correctWithBiasChange(
    const Eigen::Vector3d& delta_ba,  // 가속도 바이어스 변화량
    const Eigen::Vector3d& delta_bg,  // 자이로 바이어스 변화량
    Eigen::Vector3d& delta_p,         // 보정될 상대 위치
    Eigen::Vector3d& delta_v,         // 보정될 상대 속도
    Eigen::Matrix3d& delta_R)         // 보정될 상대 회전
{
    delta_p += J_p_ba * delta_ba + J_p_bg * delta_bg;
    delta_v += J_v_ba * delta_ba + J_v_bg * delta_bg;

    // 회전은 SO(3)에서 보정
    Eigen::Vector3d phi = J_R_bg * delta_bg;
    delta_R = delta_R * expSO3(phi);
}
```

## 💡 꼭 이해해야 할 핵심 개념

### "포즈 독립적"이란 무엇인가?

이것이 Pre-integration의 가장 핵심적인 성질입니다.

**수학적 의미:**
- Δp_ij는 R_i, p_i, v_i를 포함하지 않습니다
- Δp_ij는 오직 **IMU 측정값과 바이어스**에만 의존합니다
- 따라서 최적화로 R_i, p_i, v_i가 바뀌어도 Δp_ij는 그대로입니다

**비유 강화:**

```
[포즈 의존적]  ← 단순 적분
"강남역(37.498, 127.027)에서 출발해서
 서초구(37.484, 127.033)를 거쳐
 반포동(37.508, 127.005)에 도착"
 → 출발점 좌표가 바뀌면 모든 중간 좌표 재계산

[포즈 독립적]  ← Pre-integration
"출발점에서 남쪽 1.5km, 동쪽 0.6km 이동 후
 북서쪽 2.7km, 서쪽 2.8km 이동"
 → 출발점이 어디든 상관없이 상대 이동은 동일
```

### 단순 적분 vs Pre-integration 정리

| 항목 | 단순 적분 | Pre-integration |
|------|----------|-----------------|
| **좌표계** | 월드 (절대) | 바디 (상대) |
| **포즈 의존** | Yes | No |
| **재적분 필요** | 매 최적화 반복 | 바이어스 변화 시만 |
| **계산 비용** | O(N×M) | O(M) + O(1) 보정 |
| **자코비안** | 매번 재계산 | 사전 계산 + 재활용 |
| **실시간성** | 어려움 | 가능 |

### 왜 "Pre-integration"이라 부르는가?

- **Pre**: 미리 (최적화 전에)
- **Integration**: 적분 (IMU 데이터를 합침)
- 최적화 **전에** 미리 적분해놓는다는 뜻!

## 🔍 자체 점검 - 이해했는지 확인!

### 질문 1: 주파수 차이
**Q:** IMU가 200Hz, 카메라가 20Hz일 때, 두 키프레임 사이에 IMU 데이터는 몇 개인가요?

**A:** 약 10개입니다. 카메라 간격 50ms ÷ IMU 간격 5ms = 10. 이 10개의 IMU 데이터를 하나의 상대 측정값으로 합치는 것이 Pre-integration입니다.

### 질문 2: 재적분 문제
**Q:** 최적화가 30회 반복되고, 키프레임 사이 IMU가 10개씩 있고, 키프레임이 20개라면, 단순 적분 방식에서 총 적분 횟수는?

**A:** 30 × 10 × 19 = 5,700번입니다. Pre-integration을 쓰면 10 × 19 = 190번 (1회)이면 끝나고, 최적화 반복 때는 캐싱된 값을 재활용합니다.

### 질문 3: 포즈 독립성
**Q:** "Δp_ij가 포즈 독립적"이라는 말의 의미를 한 문장으로 설명한다면?

**A:** Δp_ij는 키프레임 i의 절대 포즈(위치, 회전, 속도)가 바뀌어도 다시 계산할 필요 없이 재활용할 수 있다는 뜻입니다.

### 질문 4: 바이어스 보정
**Q:** 바이어스가 크게 변하면 1차 근사 보정이 부정확할 수 있습니다. 이 경우 어떻게 해야 하나요?

**A:** 바이어스 변화량이 너무 크면 1차 근사가 부정확하므로, 새로운 바이어스로 처음부터 재적분(repropagate)해야 합니다. 하지만 이런 경우는 드물고, 보통은 1차 보정으로 충분합니다.
